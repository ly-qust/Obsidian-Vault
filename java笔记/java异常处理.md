该文档系统讲解了Java异常处理的完整体系，核心结论是Java通过`Throwable`类衍生的异常与错误体系，结合`try-catch-finally`、`throw`/`throws`等关键字，实现对程序异常的捕获、处理与传递，同时支持自定义异常和自动资源管理（`try-with-resources`），最终目标是提升程序的健壮性与可维护性。 ### 一、核心基础概念 #### 1. 异常的定义与本质 - **异常≠错误**：异常是程序执行中可预测的意外情况（如除以零、文件不存在），可通过代码处理；错误是脱离程序员控制的严重故障（如JVM内存溢出、栈溢出），属于`Error`类，通常无法恢复，程序一般不捕获。 - **异常产生原因**： - 用户输入非法数据（如输入非数字字符串）； - 资源操作异常（如打开不存在的文件、网络连接中断）； - 程序逻辑错误（如空指针访问、数组越界）； - 环境限制（如JVM内存不足）。 #### 2. 异常的三大类型（重点） | 类型 | 定义 | 编译要求 | 典型案例 | 处理方式 | |------|------|----------|----------|----------| | **检查性异常** | 由用户操作或环境问题引发，编译时强制要求处理 | 必须处理（`try-catch`捕获或`throws`声明） | `IOException`（文件读写异常）、`ClassNotFoundException`（类未找到） | 用`try-catch`捕获处理，或在方法上用`throws`抛给调用者 | | **运行时异常** | 由程序逻辑错误引发，编译时不强制处理 | 可选处理（可忽略，也可主动捕获） | `NullPointerException`（空指针）、`ArithmeticException`（除以零）、`ArrayIndexOutOfBoundsException`（数组越界） | 优先通过代码优化避免（如判空、校验索引），必要时捕获处理 | | **错误（Error）** | JVM或系统级故障，超出程序处理范畴 | 无需处理（也无法有效处理） | `StackOverflowError`（栈溢出）、`OutOfMemoryError`（内存溢出） | 优化程序设计（如避免递归死循环、减少内存占用），而非捕获处理 | ### 二、异常处理核心组件（关键字与类） #### 1. 核心关键字（5个） | 关键字 | 作用 | 语法位置/示例 | |--------|------|---------------| | `try` | 包裹可能抛出异常的“保护代码块” | 代码开头，后接`catch`或`finally`：<br>`try { // 可能抛异常的代码 }` | | `catch` | 捕获`try`块中抛出的指定类型异常，并处理 | 紧跟`try`，可多个（多重捕获）：<br>`catch (IOException e) { // 处理IO异常 }` | | `finally` | 无论是否发生异常，均会执行的代码块（收尾操作） | 紧跟`catch`（可选），不可单独存在：<br>`finally { // 关闭流、释放资源 }` | | `throw` | 在方法内部**手动抛出**一个具体异常对象 | 方法体中，需配合异常对象：<br>`if (num < 0) throw new IllegalArgumentException("数字不能为负");` | | `throws` | 在方法声明处**声明**该方法可能抛出的异常类型 | 方法参数列表后，可多个异常（逗号分隔）：<br>`public void readFile() throws IOException, SQLException { }` | #### 2. 核心类体系（`Throwable`为顶层父类） - **类层级关系**： `Throwable` ├─ `Error`（系统错误，如`StackOverflowError`） └─ `Exception`（所有异常的父类） ├─ 检查性异常（如`IOException`、`ClassNotFoundException`） └─ 运行时异常（`RuntimeException`子类，如`NullPointerException`、`ArithmeticException`） - **`Exception`类核心方法**（获取异常信息）： | 方法 | 作用 | 示例 | |------|------|------| | `String getMessage()` | 返回异常的详细描述信息 | `System.out.println(e.getMessage()); // 输出“文件不存在”` | | `void printStackTrace()` | 打印异常的完整调用栈（定位错误位置关键） | `e.printStackTrace(); // 控制台输出异常发生的类、方法、行号` | | `String toString()` | 返回异常的简短描述（类名+信息） | `System.out.println(e.toString()); // 输出“java.io.FileNotFoundException: test.txt”` | ### 三、异常处理实战场景（重点） #### 1. 基础捕获：`try-catch`与`finally` - **场景**：处理单个异常，确保资源释放（如关闭文件流）。 - **示例代码**： ```java public class FileReadTest { public static void main(String[] args) { FileReader reader = null; try { // 可能抛异常的代码：读取不存在的文件 reader = new FileReader("test.txt"); int data = reader.read(); System.out.println((char) data); } catch (FileNotFoundException e) { // 处理“文件未找到”异常 System.out.println("错误：文件不存在 -> " + e.getMessage()); } catch (IOException e) { // 处理“读取IO异常”（多重捕获，子类异常在前） System.out.println("错误：文件读取失败 -> " + e.getMessage()); } finally { // 无论是否异常，均关闭流（资源释放） try { if (reader != null) reader.close(); } catch (IOException e) { System.out.println("关闭流失败：" + e.getMessage()); } } } } ``` - **关键注意点**： - 多重`catch`块中，**子类异常必须在前**（如`FileNotFoundException`是`IOException`子类，需先捕获），否则编译报错； - `finally`块中避免抛出新异常，以免覆盖原异常。 #### 2. 自动资源管理：`try-with-resources`（JDK 7+） - **场景**：替代`finally`手动关闭资源，自动关闭实现`AutoCloseable`接口的资源（如`FileReader`、`BufferedReader`、数据库连接）。 - **核心优势**：代码更简洁，避免遗漏资源关闭，自动处理关闭时的异常。 - **示例代码**（对比传统`finally`）： ```java // try-with-resources写法（自动关闭BufferedReader） public class TryWithResourcesTest { public static void main(String[] args) { // 资源声明在try后括号中，多个资源用分号分隔 try (BufferedReader br = new BufferedReader(new FileReader("test.txt"))) { String line = br.readLine(); while (line != null) { System.out.println(line); line = br.readLine(); } } catch (IOException e) { System.out.println("文件处理异常：" + e.getMessage()); } // 无需手动关闭br，JVM自动关闭（无论是否异常） } } ``` - **关键规则**： - 资源必须实现`AutoCloseable`接口（Java标准IO类、数据库连接类均已实现）； - 多个资源声明时，关闭顺序与声明顺序**相反**（如先关`BufferedReader`，再关`FileReader`）。 #### 3. 异常传递：`throw`与`throws` - **场景1：手动抛异常（`throw`）**：当业务逻辑不满足条件时，主动抛出异常（如参数校验）。 ```java public void checkAge(int age) { if (age < 0 || age > 150) { // 手动抛出运行时异常（无需在方法上声明throws） throw new IllegalArgumentException("年龄必须在0-150之间，当前为：" + age); } } ``` - **场景2：声明异常（`throws`）**：方法内部无法处理异常时，抛给调用者处理（常用于检查性异常）。 ```java // 方法声明抛出IOException（检查性异常），调用者必须处理 public void readFile(String path) throws IOException { FileReader reader = new FileReader(path); reader.read(); // 未处理IOException，需在方法上用throws声明 } // 调用者处理方式1：try-catch捕获 public static void main(String[] args) { try { readFile("test.txt"); } catch (IOException e) { e.printStackTrace(); } } // 调用者处理方式2：继续throws抛给上层（如main方法抛给JVM） public static void main(String[] args) throws IOException { readFile("test.txt"); // 异常最终由JVM处理（打印栈信息） } ``` #### 4. 自定义异常 - **场景**：业务场景需要特定异常（如“余额不足”“权限不够”），需继承`Exception`（检查性）或`RuntimeException`（运行时）。 - **实现步骤**： 1. 定义异常类，继承`Exception`或`RuntimeException`； 2. 提供构造方法（默认构造、带消息的构造，可选带原因的构造）； 3. （可选）添加自定义字段或方法（如“余额不足”异常中添加“缺少金额”字段）。 - **示例代码**（银行余额不足异常）： ```java // 1. 自定义检查性异常（继承Exception） class InsufficientFundsException extends Exception { private double lackAmount; // 自定义字段：缺少的金额 // 带消息和缺少金额的构造 public InsufficientFundsException(String message, double lackAmount) { super(message); this.lackAmount = lackAmount; } // 自定义方法：获取缺少的金额 public double getLackAmount() { return lackAmount; } } // 2. 业务类：银行账户 class BankAccount { private double balance; // 取钱方法：抛出自定义异常 public void withdraw(double amount) throws InsufficientFundsException { if (amount > balance) { double lack = amount - balance; // 手动抛出自定义异常 throw new InsufficientFundsException("取钱金额超过余额", lack); } balance -= amount; } } // 3. 调用者：处理自定义异常 public class BankTest { public static void main(String[] args) { BankAccount account = new BankAccount(); account.deposit(500); // 假设已实现deposit方法 try { account.withdraw(800); // 取钱800，余额仅500 } catch (InsufficientFundsException e) { // 调用自定义方法获取缺少金额 System.out.println(e.getMessage() + "，缺少：" + e.getLackAmount() + "元"); } } } ``` - **关键选择**： - 若异常需强制处理（如“余额不足”需业务层处理），继承`Exception`（检查性）； - 若异常是逻辑错误（如“参数格式错误”），继承`RuntimeException`（运行时，可选处理）。 ### 四、Java内置异常类（常用） #### 1. 运行时异常（`RuntimeException`子类，无需强制处理） | 异常类 | 触发场景 | |--------|----------| | `NullPointerException` | 调用`null`对象的方法或属性（如`String s = null; s.length();`） | | `ArithmeticException` | 非法算术运算（如`10 / 0`） | | `ArrayIndexOutOfBoundsException` | 数组索引越界（如`int[] arr = new int[2]; arr[3] = 1;`） | | `ClassCastException` | 类型强制转换失败（如`Object obj = "hello"; Integer i = (Integer) obj;`） | | `IllegalArgumentException` | 方法参数非法（如`checkAge(-1)`） | | `NumberFormatException` | 字符串转数字失败（如`Integer.parseInt("abc")`） | #### 2. 检查性异常（需强制处理） | 异常类 | 触发场景 | |--------|----------| | `IOException` | IO操作异常（如文件读写、网络连接） | | `FileNotFoundException` | 打开不存在的文件（`new FileReader("不存在的文件.txt")`） | | `ClassNotFoundException` | 加载不存在的类（如`Class.forName("com.xxx.NoSuchClass")`） | | `InterruptedException` | 线程被中断（如`Thread.sleep(1000)`时线程被打断） | | `SQLException` | 数据库操作异常（如SQL语法错误、连接失败） | ### 五、异常处理最佳实践（重点） 1. **精确捕获异常，避免“万能捕获”**： 不推荐用`catch (Exception e) {}`捕获所有异常，应捕获具体异常（如`catch (IOException e)`），避免掩盖未知错误。 2. **优先处理异常，而非“吞掉异常”**： 禁止空`catch`块（`catch (Exception e) {}`），至少打印异常信息（`e.printStackTrace()`），便于定位问题。 3. **用`try-with-resources`管理资源**： 处理IO流、数据库连接等资源时，优先使用`try-with-resources`，避免手动关闭资源遗漏导致泄露。 4. **异常信息需明确，包含关键上下文**： 抛异常时添加详细消息（如`throw new IllegalArgumentException("用户ID不能为空，当前为：" + userId)`），而非模糊消息（如`throw new IllegalArgumentException("参数错误")`）。 5. **避免在`finally`块中修改返回值**： `finally`块的返回值会覆盖`try`/`catch`块的返回值，导致逻辑混乱（如`try { return 1; } finally { return 2; }`最终返回2）。 6. **运行时异常优先通过代码优化避免**： 如`NullPointerException`可通过判空避免（`if (obj != null) { obj.doSomething(); }`），`ArrayIndexOutOfBoundsException`可通过校验索引避免（`if (index >= 0 && index < arr.length)`）。 7. **自定义异常命名规范**： 异常类名以`Exception`结尾（如`InsufficientFundsException`），清晰标识异常类型，便于代码理解。 ### 六、核心总结 Java异常处理的核心是“**预测意外、优雅处理**”： - 通过`try-catch`捕获可处理的异常，用`finally`或`try-with-resources`确保资源释放； - 用`throw`手动触发业务异常，用`throws`传递无法处理的异常； - 区分检查性异常（强制处理）、运行时异常（优化避免）与错误（无法处理），选择合适的处理策略； - 遵循最佳实践，确保异常信息清晰、代码简洁，最终提升程序的稳定性与可维护性。
