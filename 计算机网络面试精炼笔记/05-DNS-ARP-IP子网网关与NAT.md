# DNS、ARP、IP、子网、网关与 NAT

> 当前面试主入口：[[计算机网络面试精炼笔记/00-计算机网络知识地图]]

## 一句话结论

DNS 解决名字到地址，ARP 解决本地下一跳 IP 到 MAC，IP 负责跨网寻址，子网和网关决定路径，NAT 在地址边界转换通信视图。

## 1. DNS 与寻址因果链

```text
应用查询域名
→ 先查浏览器/系统/本地 DNS 缓存
→ 递归解析器查询根、顶级域和权威 DNS
→ 获得 A/AAAA/CNAME 等记录
→ 按 TTL 缓存并向目标 IP 发起连接
```

DNS 失败和 TCP 失败不是一回事；解析成功也不代表目标端口可达。排查要记录查询类型、缓存、TTL、解析器和最终地址。

## 2. IP、子网与网关

- IP 地址用于网络层寻址；子网掩码/CIDR 前缀划分网络部分和主机部分。
- 发送方先判断目标 IP 是否与自己同一子网：同网段通常直接交付，跨网段交给默认网关。
- 默认网关是主机把非本地目标交给的下一跳路由器，不是“所有请求的服务器”。
- 路由表决定下一跳和出口网卡；多个网卡、容器网络和策略路由会让结果更复杂。

## 3. ARP 与 NAT

- ARP 在本地链路广播询问“谁拥有这个 IP”，获得下一跳的 MAC；跨网段时通常解析网关 MAC，不是直接解析远端服务器 MAC。
- NAT 在边界设备上改写源/目标地址或端口，使私网地址与公网地址之间建立映射；它能缓解地址不足并隐藏内部拓扑，但会增加连接追踪和入站访问复杂度。
- NAT 不等于防火墙，是否允许访问仍由安全策略和端口映射决定。

## 4. 高频面试回答

> 访问域名时先经过 DNS 得到 IP，再由子网判断目标是否本地可达；本地链路通过 ARP 获取下一跳 MAC，跨网段就把 IP 包交给默认网关。路由器按路由表转发，经过 NAT 时可能改写地址和端口。DNS、ARP、路由、端口和应用协议是不同层次，排障要逐层确认。

## 5. Java / Linux / SmartRenew 关联

- Java HTTP 客户端看到连接超时，可能卡在 DNS、路由、TCP 或 TLS，不能只看业务代码；原始网络概念见 [[java笔记/17网络编程]]。
- Linux 用 `ip addr` 看地址和网卡、`ip route` 看路由、`ip neigh` 看邻居/ARP、`ping` 和 `curl` 做分层验证，见 [[Linux/命令操作]]、[[Linux/未命名]]。
- Nginx 部署时要区分客户端到 Nginx、Nginx 到后端两段连接，反向代理资料见 [[nginx/nginx(linux)]]、[[nginx/nginx讲解]]。
- SmartRenew 的前端、Nginx、Java 服务、MQ/外部依赖可能处在不同网络边界；要分别记录入口地址、Host、端口、代理和 trace_id，项目请求链见 [[SR/SmartRenew面试精炼笔记/00-SmartRenew项目知识地图]]。

## 容易答错

- DNS 把域名解析成 IP，不负责保证 TCP 端口或业务可用。
- ARP 只解决本地链路的下一跳 MAC，跨网段不是查询远端 MAC。
- 网关不是 DNS，也不是目标应用服务本身。
- NAT 改写地址/端口，不等于可靠传输、负载均衡或完整防火墙。
- 私网 IP 在不同网络中可以重复，不能简单说“IP 全网唯一”。

## 高频追问

1. 为什么跨网段要找网关 MAC？——二层只能把帧交给本地下一跳，三层 IP 包由路由器继续转发。
2. DNS 解析成功但 curl 失败怎么查？——继续查路由、端口监听、防火墙、TCP、TLS 和 HTTP 响应。
3. NAT 为什么能让多个内网主机共享公网 IP？——通过源端口等信息建立映射，返回流量按映射找到内网连接。
