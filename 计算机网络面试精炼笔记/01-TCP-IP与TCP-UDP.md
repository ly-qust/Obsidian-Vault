# TCP/IP 与 TCP/UDP

> 当前面试主入口：[[计算机网络面试精炼笔记/00-计算机网络知识地图]]

## 一句话结论

TCP/IP 是分层协作的协议族，TCP 用连接、序号、确认和重传换可靠性，UDP 保留数据报边界并把可靠性和时延控制更多交给应用。

## 1. TCP/IP 分层

| 层次 | 解决什么问题 | 常见例子 |
|---|---|---|
| 应用层 | 业务消息和资源语义 | HTTP、DNS、WebSocket |
| 传输层 | 进程到进程、端口、传输控制 | TCP、UDP |
| 网际层 | 跨网络寻址和路由 | IP、ICMP |
| 网络接口层 | 本地链路和帧传输 | Ethernet、Wi-Fi、ARP |

发送时逐层封装，接收时逐层解封装。分层的价值是让应用不必直接处理网卡和路由细节，同时每一层都可能成为排障边界。

## 2. TCP 与 UDP 对比

| 维度 | TCP | UDP |
|---|---|---|
| 连接 | 面向连接，有建立/释放过程 | 无连接，直接发送数据报 |
| 数据形态 | 字节流，无消息边界 | 数据报，有边界 |
| 可靠性 | 序号、确认、重传、校验等 | 不保证到达、有序或去重 |
| 流量/拥塞 | 协议内置控制 | 通常由应用或上层协议负责 |
| 适合场景 | HTTP、文件、数据库连接等 | 实时音视频、DNS查询、广播等 |

“UDP 更快”不是绝对结论：它减少连接和可靠性控制，但丢包、重传、乱序处理可能转移到应用，最终要看场景和实现。

## 3. 高频面试回答

> TCP 面向连接、面向字节流并提供可靠有序传输，代价是握手、确认、重传和拥塞控制；UDP 面向数据报、无连接，延迟和控制开销较低，但不保证可靠性。选择时看消息边界、可靠性、时延、广播以及应用是否有自己的纠错和重传机制。

## 4. 因果链

```text
应用产生消息
→ 传输层按端口交给目标进程
→ IP 按地址和路由选择下一跳
→ 链路层封装本地帧并发送
→ 对端逐层解封装
→ TCP/UDP 将数据交给对应 Socket
→ 应用解析业务协议
```

## 容易答错

- TCP 是字节流，不保留应用层消息边界；一次 `read` 不等于一次业务消息。
- UDP 有校验和等基础能力，但不等于可靠传输。
- IP 地址标识网络层接口/主机寻址，端口用于传输层进程复用，不能混为一谈。
- OSI 七层和 TCP/IP 四层是不同抽象，不要机械逐层一一对应。

## 高频追问

1. TCP 为什么可靠？——通过序号、确认、超时重传、校验和窗口等机制协作，不是因为链路永不丢包。
2. 为什么 HTTP 常用 TCP？——请求/响应通常需要可靠有序字节流，连接管理交给 TCP。
3. UDP 适合什么？——对时延、消息边界或广播更敏感，且应用能接受丢包或自行补偿的场景。
