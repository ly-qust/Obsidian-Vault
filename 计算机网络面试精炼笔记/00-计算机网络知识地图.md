## 推荐复习路径

```text
TCP/IP 分层与 TCP/UDP
→ 握手/挥手/TIME_WAIT
→ 可靠传输/流量/拥塞
→ HTTP/HTTPS/TLS
→ DNS/ARP/IP/子网/网关/NAT
→ WebSocket 与长连接
→ Linux/Nginx 分层排障
→ [[计算机网络面试精炼笔记/08-高频面试与央企笔试自测]]
```

## 一条因果链

```text
输入域名/URL
→ DNS 得到 IP
→ 判断目标是否同子网，必要时经网关/NAT
→ ARP 找到本地下一跳的 MAC
→ TCP 建连或 UDP 直接发送
→ HTTP/TLS/WebSocket 处理应用语义
→ 通过状态码、抓包、端口、日志定位故障
```

## 高频面试回答

> 一次 Java 或 AI 应用请求，先由 DNS 把域名解析为 IP，再根据子网判断直连还是交给网关，局域网内通过 ARP 找下一跳 MAC；传输层按可靠性和时延需求选择 TCP 或 UDP，应用层再承载 HTTP、HTTPS 或 WebSocket。排障时从本机配置、路由、端口监听、TCP 连接、TLS/HTTP 响应到 Nginx 和后端日志逐层缩小范围。

## 容易答错

- TCP 可靠不等于业务请求一定成功；应用仍要处理超时、重试、幂等和状态码。
- HTTPS 不是另一种传输层协议，而是 HTTP 经 TLS 保护后的应用通信。
- 长连接、Keep-Alive、WebSocket 不是同一个概念；要区分连接复用和双向消息通道。
- `ping` 通不代表 TCP 端口、TLS、HTTP 和后端业务都正常。
- IEEE 802、VLAN、STP 等笔试扩展不复制到主干，继续回看 [[IEEE]]。
