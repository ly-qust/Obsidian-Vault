# 三次握手、四次挥手与 TIME_WAIT

> 当前面试主入口：[[计算机网络面试精炼笔记/00-计算机网络知识地图]]

## 一句话结论

三次握手确认双方收发能力和初始序号，四次挥手分别关闭两个方向的数据流，主动关闭方进入 TIME_WAIT 以吸收旧报文并确认最后 ACK。

## 1. 三次握手

```text
客户端 → SYN(seq=x) → 服务端
客户端 ← SYN+ACK(seq=y, ack=x+1) ← 服务端
客户端 → ACK(ack=y+1) → 服务端
```

因果链：

```text
客户端申请建立连接
→ 服务端确认收到并声明自己的初始序号
→ 客户端确认服务端的序号
→ 双方都知道对方具备发送和接收能力
→ 连接进入可传输状态
```

三次不是为了“把连接变成三份”，而是为了避免历史重复 SYN 造成错误连接，并让双方交换序号和确认信息。

## 2. 四次挥手

```text
主动关闭方 → FIN → 被动方
主动关闭方 ← ACK ← 被动方
被动方 → FIN → 主动方
被动方 ← ACK ← 主动方
```

TCP 是全双工，两个方向需要分别关闭；被动方收到 FIN 后仍可能发送剩余数据，所以 ACK 和 FIN 通常不是同一个时刻发出，这就是常说的“四次”。

## 3. TIME_WAIT

主动关闭方通常在最后 ACK 后进入 TIME_WAIT：

- 给最后 ACK 留出重传机会：如果对方没收到 ACK，可以重发 FIN。
- 让旧连接中的延迟报文自然过期，避免污染后续使用相同四元组的连接。
- 常用 `2MSL` 解释等待时长，但 MSL 的具体数值和实现策略不要硬背成固定秒数。

端口频繁短连接时，TIME_WAIT 数量可能增多；应先判断连接模式、主动关闭方、端口范围和系统参数，不能把“开启复用”当作万能修复。

## 4. 高频面试回答

> 三次握手是 SYN、SYN-ACK、ACK，核心是互相确认收发能力并同步初始序号；四次挥手是因为 TCP 全双工，两个方向独立关闭。主动关闭方进入 TIME_WAIT，主要用于重传最后 ACK 和让旧报文过期，常按 2MSL 解释。

## 容易答错

- 三次握手不是三次数据传输，也不是为了防止所有攻击。
- 四次挥手不是固定每次都严格四个独立报文；ACK 和 FIN 可能合并。
- TIME_WAIT 不一定在服务端；谁主动关闭，谁更可能进入 TIME_WAIT。
- `TIME_WAIT` 不是“连接还在处理业务”，而是主动关闭方的 TCP 状态。

## 高频追问

1. 为什么握手不能两次？——两次无法让发起方确认服务端已经收到自己的最终确认并具备双向收发条件。
2. 为什么挥手需要四次？——两个方向独立关闭，被动方可能还有数据要发送。
3. TIME_WAIT 太多怎么看？——先确认主动关闭方和短连接模式，再看端口、连接池、超时、重试和系统参数。
