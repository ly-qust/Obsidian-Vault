# 高频面试与央企笔试自测

> 当前面试主入口：[[计算机网络面试精炼笔记/00-计算机网络知识地图]]
> 先遮住参考要点闭答，再根据岗位补 Java、Linux 或 SmartRenew 场景。

## 一句话结论

网络自测要能把协议定义、报文因果、工程边界和排障证据连成一条链，而不是只背名词。

## 自测题与参考要点

### 1. TCP/IP 分层分别解决什么问题？

参考要点：应用语义、进程间传输、跨网络寻址、本地链路传输；分层封装和解封装。

### 2. TCP 和 UDP 如何选择？

参考要点：TCP 可靠有序字节流；UDP 无连接数据报，边界和时延更灵活，可靠性由应用决定。

### 3. 三次握手每一步做什么？

参考要点：SYN、SYN-ACK、ACK；确认双方收发能力并同步初始序号。

### 4. 为什么挥手常说四次？

参考要点：TCP 全双工，两个方向独立关闭；ACK 与 FIN 可能合并，不能死背固定四个包。

### 5. TIME_WAIT 为什么存在？

参考要点：重传最后 ACK、等待旧报文过期；通常由主动关闭方进入，时长常用 2MSL 解释。

### 6. TCP 如何做到可靠传输？

参考要点：序号、确认、校验、超时/快速重传、窗口和有序交付；不保证业务 exactly-once。

### 7. 流量控制和拥塞控制区别是什么？

参考要点：`rwnd` 保护接收方，`cwnd` 反映网络承载；实际窗口受二者较小值限制。

### 8. HTTP 200 是否代表业务成功？

参考要点：只代表 HTTP 层响应成功，业务还要看响应体、业务码、幂等和数据状态。

### 9. HTTPS 比 HTTP 多了什么？

参考要点：TLS 提供身份认证、机密性和完整性；握手协商会话密钥，数据阶段主要使用对称加密。

### 10. DNS、ARP、网关分别做什么？

参考要点：DNS 名字到 IP，ARP 本地下一跳 IP 到 MAC，网关承接非本地网段的下一跳。

### 11. 子网掩码如何影响发送路径？

参考要点：划分网络/主机部分；先判断目标是否同网段，同网段直交付，跨网段交给默认网关。

### 12. NAT 解决什么问题？

参考要点：在地址边界改写地址/端口并维护映射；不等于防火墙、可靠传输或负载均衡。

### 13. WebSocket 和 HTTP Keep-Alive 区别是什么？

参考要点：Keep-Alive 复用 HTTP 连接；WebSocket Upgrade 后提供双向消息通道，还要处理心跳、重连和背压。

### 14. 网络故障排查顺序怎么说？

参考要点：DNS → IP/路由 → 端口 → TCP → TLS → HTTP → Nginx/后端日志和依赖。

### 15. `ping` 通但 HTTP 访问失败，可能是什么？

参考要点：端口未监听、防火墙、TCP/TLS、Host/路径、Nginx 代理、应用状态码或后端超时。

### 16. 502 和 504 如何初步区分？

参考要点：都要看 Nginx error log 和上游；502 更偏上游连接/响应无效，504 更偏上游在代理超时内未完成，具体仍以配置和日志为准。

### 17. Java 请求偶发超时如何拆分？

参考要点：DNS、connect、TLS、write、read、总耗时；再看连接池、重试、服务端排队和下游依赖。

### 18. SmartRenew 如何避免网络重试造成重复业务？

参考要点：幂等键/唯一约束、状态机、超时分类、有限重试和补偿；TCP ACK 不能代替业务确认。

### 19. 央国企笔试中的 IEEE 802、VLAN、STP 放哪里？

参考要点：作为计算机网络笔试补充 Reference，继续回看 [[IEEE]]，不混入本目录的 Java/运维面试主干。

### 20. 如何用一句话回答“网络分层排障”？

参考要点：每一层提出一个可验证假设，用命令、抓包、状态码和日志逐层排除，最后回到业务语义验证。

## 因果链复述

```text
域名
→ DNS
→ IP/子网/网关/ARP
→ TCP/UDP
→ TLS
→ HTTP/WebSocket
→ Nginx/Java/SmartRenew业务
→ 日志、指标、抓包和重试证据
```

## 高频面试回答

> 面试先给定义，再给因果链，最后落到一个 Java、Linux 或 SmartRenew 例子；如果是故障题，就按 DNS、路由、端口、TCP、TLS、HTTP、网关、后端的顺序给证据，不直接猜某个协议参数。

## 容易答错

- 不把 IEEE 802 大量内容复制进主干，[[IEEE]] 继续承担央国企笔试补充 Reference。
- 不把 TCP 可靠、HTTP 200、TLS 成功和业务提交成功混为一谈。
- 不把 Keep-Alive、WebSocket、连接池和 TCP Keep-Alive 说成同一个机制。
- 不用单个 `ping` 或 `curl` 结果替代分层证据。
