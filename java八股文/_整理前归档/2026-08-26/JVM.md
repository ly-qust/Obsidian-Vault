# JVM 主线面试复习

## 1. JVM 总图

```text
Java源码
→ javac编译
→ .class字节码
→ JVM类加载
→ 执行引擎运行

JVM
├── Runtime Data Areas
├── Object Allocation
├── Reachability / GC Roots
├── GC Algorithms
├── Generational GC
├── Collectors
└── OOM / Dump
```

## 2. 运行时数据区

| 区域 | 主要内容 | 私有/共享 | 典型问题 |
|---|---|---|---|
| 程序计数器 | 当前线程执行位置 | 线程私有 | 通常不作为常规 OOM 重点 |
| Java虚拟机栈 | Java方法栈帧、局部变量等 | 线程私有 | `StackOverflowError` |
| 本地方法栈 | Native方法执行信息 | 线程私有 | 栈相关错误 |
| 堆 | 普通对象实例、数组 | 线程共享 | `OutOfMemoryError: Java heap space` |
| 方法区 | 类相关信息 | 线程共享 | 类元数据相关 OOM |
| 元空间 | HotSpot JDK 8+ 类元数据主要存放位置，使用本地内存 | 方法区的常见实现相关 | `OutOfMemoryError: Metaspace` |

```java
User user = new User();
```

粗略理解：局部引用 `user` 在当前方法栈帧中，`new User()` 对象通常在堆中。

记忆：**三私有：PC、Java栈、Native栈；两共享：堆、方法区。**

## 3. 对象创建

```text
检查类是否已经加载
→ 为对象分配内存
→ 零值初始化
→ 设置对象头
→ 执行构造方法
→ 返回对象引用
```

内存分配：

- 内存规整：指针碰撞。
- 内存碎片化：空闲列表。
- TLAB：位于共享堆中，由线程优先使用，减少多线程分配竞争。

边界：普通对象通常在堆中，但 JIT 可能通过逃逸分析和标量替换，使对象不一定以完整形式实际存在于堆中。

## 4. 对象存活判断

HotSpot 主流 GC 的核心是可达性分析：

```text
GC Roots
↓ 沿引用链搜索
能到达对象 → 存活
不能到达 → 进入可回收判断范围
```

典型 GC Roots：

1. 当前线程栈中正在引用的对象。
2. 静态字段引用的对象。
3. JNI / Native 引用的对象。
4. JVM 内部的重要对象。

引用计数的问题：对象可以互相循环引用，但整个对象环已经无法从 GC Roots 到达，引用计数仍可能不为 0。

## 5. 三种 GC 算法

| 算法 | 核心思想 | 优点 | 问题 |
|---|---|---|---|
| 标记—清除 | 标记后释放垃圾空间 | 不必复制全部存活对象 | 内存碎片 |
| 复制 | 复制存活对象，旧区域整体清空 | 空间规整、分配方便 | 额外空间；存活对象多时成本高 |
| 标记—整理 | 存活对象向一端移动 | 减少碎片，形成连续空间 | 移动对象和更新引用成本高 |

## 6. 分代、STW、并行与并发

```text
Heap
├── Young：刚创建、通常很快死亡的对象
└── Old：经历多次回收后仍然存活的对象
```

- 新生代：创建对象多，但一次 GC 后存活对象通常较少，适合复制思想。
- 老年代：存活对象比例高，机械复制成本大，更适合标记、整理等思路。
- Young GC：主要针对新生代，通常较频繁。
- Full GC：通常涉及更大范围，成本和停顿风险更高；不同收集器行为存在差异。

```text
STW：GC某些关键阶段暂停用户线程
并行：多个GC线程同时回收，偏吞吐
并发：GC线程与用户线程某些阶段同时推进，偏低停顿
```

并发 GC 仍可能存在 STW。

## 7. 常见垃圾收集器

| 收集器 | 主干特点 | 定位/问题 |
|---|---|---|
| Serial | 单GC线程，回收时STW | 简单，停顿明显 |
| Parallel | 多GC线程并行回收 | 吞吐量优先 |
| CMS | 老年代部分阶段与用户线程并发 | 降低停顿；碎片、CPU竞争、仍有STW；历史收集器 |
| G1 | 堆划分为多个Region，按收益选择回收区域 | 大堆下兼顾吞吐与相对可预测停顿 |

CMS 与 G1：CMS 接近传统分代布局且碎片较明显；G1 使用动态承担 Eden、Survivor、Old 角色的 Region，更便于选择和整理回收区域。

补充：ZGC 等现代收集器主要定位低延迟。【后续深入】

## 8. OOM、StackOverflow 与 Dump

```text
无限递归
→ 栈帧不断入栈
→ 虚拟机栈耗尽
→ StackOverflowError
```

```text
不断创建对象并保留引用
→ 对象仍可达
→ GC无法回收
→ 堆耗尽
→ OutOfMemoryError: Java heap space
```

| Dump | 主要用途 |
|---|---|
| Heap Dump | 对象数量、内存占用、支配关系、到 GC Roots 的引用链 |
| Thread Dump | 线程执行位置、阻塞、等待、锁和死锁 |

OOM 最小排查链：

```text
确认内存持续上涨
→ 判断Heap/线程问题
→ 获取对应Dump
→ 查看大对象或线程状态
→ 查看GC Roots引用链
→ 定位为什么没有释放
→ 回到业务代码
```

## 9. 四道口述题

### 题1：JVM 运行时数据区有哪些？

30 秒核心版：

> 线程私有区域包括程序计数器、Java 虚拟机栈和本地方法栈；线程共享区域包括堆和方法区。堆主要存对象和数组，虚拟机栈保存方法调用产生的栈帧，方法区保存类相关信息，HotSpot JDK 8+ 的类元数据主要位于元空间。

60～90 秒面试版：

> JVM 运行时数据区可以按线程私有和线程共享划分。线程私有的程序计数器记录线程执行位置，Java 虚拟机栈保存 Java 方法调用对应的栈帧，本地方法栈服务于 Native 方法。线程共享的堆通常存放对象实例和数组，是 GC 的主要区域；方法区保存类结构、方法等类相关信息，HotSpot JDK 8 以后类元数据主要放在使用本地内存的元空间。虚拟机栈耗尽常见 `StackOverflowError`，堆耗尽可能出现 Java Heap OOM。

追问：

1. `user` 引用与 `new User()` 分别在哪里？
2. 为什么程序计数器和虚拟机栈线程私有？

### 题2：对象创建过程是什么？

30 秒核心版：

> JVM 先检查类是否加载，再分配内存、进行零值初始化、设置对象头、执行构造方法，最后返回对象引用。

60～90 秒面试版：

> 执行 `new` 时，JVM 首先检查目标类是否已经加载；随后根据对象大小分配内存，内存规整时可使用指针碰撞，不规整时可通过空闲列表寻找空间。接着把实例字段初始化为零值，设置对象头等运行信息，再执行构造方法完成业务初始化，最后把引用返回给调用者。HotSpot 还可能使用 TLAB 减少多线程分配竞争。普通对象通常位于堆中，但 JIT 可能通过逃逸分析和标量替换进行优化，所以不宜说所有对象一定以完整形式存在于堆中。

追问：

1. 零值初始化与构造方法谁先执行？
2. 什么是 TLAB？

### 题3：JVM 如何判断对象是否需要回收？

30 秒核心版：

> JVM 主要通过可达性分析，从 GC Roots 沿引用链搜索。能到达的对象存活，完全不可达的对象进入可回收判断范围。典型 Roots 包括线程栈引用、静态字段引用、JNI 引用和 JVM 内部对象。

60～90 秒面试版：

> HotSpot 主流垃圾收集器的核心判断方式是可达性分析。JVM 选择一组当前确定存活的起始引用作为 GC Roots，然后沿对象引用链搜索。能从 Roots 到达的对象仍然存活，无法从任何 Root 到达的对象进入可回收判断范围。典型 Roots 包括当前线程栈中的引用、静态字段引用、JNI 或 Native 引用，以及类加载器、活跃线程等 JVM 内部对象。简单引用计数无法正确处理循环引用，例如 A、B 互相引用但整个环已与 Roots 断开，计数仍不为零。

追问：

1. 不可达对象是否一定立刻释放？
2. 两个对象互相引用还能回收吗？

### 题4：常见 GC 算法和收集器怎么理解？

30 秒核心版：

> 标记—清除直接释放垃圾但产生碎片；复制算法复制少量存活对象，适合新生代；标记—整理移动存活对象形成连续空间。Serial 单线程，Parallel 偏吞吐，CMS 历史上偏低停顿但碎片明显，G1 通过 Region 在大堆下兼顾吞吐和停顿目标。

60～90 秒面试版：

> 三种基础算法中，标记—清除不移动存活对象，但会留下碎片；复制算法把存活对象复制到另一块区域后整体清空旧区域，空间规整，适合对象死亡率高的新生代；标记—整理把存活对象向一端移动，减少碎片，但移动和更新引用成本较高。JVM 分代是因为大多数对象生命周期短，少部分长期存活，可以针对不同区域采用更合适的策略。收集器方面，Serial 是单线程回收，Parallel 偏吞吐量，CMS 通过部分并发阶段降低老年代停顿但存在碎片和 CPU 竞争，G1 使用 Region 组织堆，在大堆场景下兼顾吞吐和相对可预测的停顿目标。

追问：

1. 并行与并发有什么区别？
2. G1 为什么使用 Region？
