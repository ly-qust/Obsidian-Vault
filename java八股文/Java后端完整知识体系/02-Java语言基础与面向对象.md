# Java 语言基础与面向对象

## 一句话结论

Java 基础题考的是你能否准确解释“变量里存什么、方法如何分派、对象如何保持边界”，而不是背关键字列表。

## 一、编译、字节码与运行

```text
.java 源文件
→ javac 词法/语法/类型检查
→ .class 字节码
→ 类加载与字节码验证
→ 解释执行/JIT编译
→ CPU执行机器码
```

- Java 是静态类型语言；大部分类型错误在编译期发现。
- 字节码提供跨平台中间表示，“一次编译，到处运行”依赖目标机器上的 JVM。
- JVM 可以解释热点代码，也可以通过 JIT 编译为本地机器码；不要把 Java 简化为纯解释型语言。
- JDK 包含开发工具和运行时；JVM 是执行规范及实现核心；JRE 作为历史分发概念在现代 JDK 中不再是必须单独安装的产品形态。

## 二、基本类型与包装类型

| 类型 | 位数/语义 | 高频边界 |
|---|---|---|
| byte/short/int/long | 有符号整数 | 溢出不会自动抛异常 |
| float/double | IEEE 754 浮点 | 不适合直接表示精确金额 |
| char | UTF-16 code unit | 不一定代表完整 Unicode 字符 |
| boolean | true/false | 存储大小不由语言规范固定为 1 bit |

金额优先使用 `BigDecimal`：

```java
BigDecimal amount = new BigDecimal("0.10");
BigDecimal total = amount.multiply(BigDecimal.valueOf(3));
```

不要使用 `new BigDecimal(0.1)`，因为二进制浮点近似值已经进入构造参数。

包装类型注意：

- 自动装箱/拆箱会引入空指针风险：`Integer x = null; int y = x;`。
- `Integer` 小值缓存导致部分 `==` 看似成立；对象数值比较使用 `equals` 或拆箱后比较。
- 频繁装箱会增加对象和 GC 压力，性能敏感路径优先使用基本类型或专用数据结构。

## 三、Java 只有值传递

方法调用时复制的是变量当前保存的值：基本类型复制数值，对象变量复制引用值。

```java
void change(User u) {
    u.setName("new");    // 通过复制的引用修改同一个对象
    u = new User();      // 只改变局部变量 u，不改变调用方变量
}
```

错误回答：“对象按引用传递”。准确回答：Java 始终值传递，对象场景传递的是引用值的副本。

## 四、String 与不可变性

- `String` 对外不可变，便于缓存 hash、安全共享、字符串池复用和并发使用。
- 拼接少量常量可由编译器优化；循环拼接使用 `StringBuilder`。
- `StringBuilder` 不保证线程安全；`StringBuffer` 方法同步但通常不应作为并发设计的默认方案。
- `equals` 比内容，`==` 比较基本值或引用是否相同。
- 字符串池优化相同字面量，但不要依赖 `intern()` 解决业务内存问题。

## 五、封装、继承与多态

### 封装

把状态与约束放在对象内部，通过方法维持不变量。例如 Voucher 不能允许外部随意把状态从 USED 改回 ACTIVE。

### 继承

表达稳定的 is-a 关系。继承会耦合父类实现，业务组合通常比深层继承更灵活。

### 多态

父类型引用指向子类型对象；调用被重写的实例方法时，运行期根据实际对象分派。

```java
PaymentService service = new WechatPaymentService();
service.pay(); // 调用子类重写实现
```

字段、静态方法和私有方法不参与同样的动态分派。重载主要在编译期根据参数类型选择；重写是子类替换父类实例方法实现。

## 六、重载与重写

| 对比 | 重载 Overload | 重写 Override |
|---|---|---|
| 范围 | 同类或继承体系 | 子类覆盖父类方法 |
| 参数列表 | 必须不同 | 必须相同 |
| 返回值 | 不能仅靠返回值区分 | 可协变返回 |
| 绑定 | 编译期 | 运行期动态分派 |
| 访问权限 | 无特殊收窄规则 | 不能比父类更严格 |
| 异常 | 独立 | 受检异常不能更宽 |

## 七、接口与抽象类

- 接口表达能力契约，可多实现；适合解耦策略和基础设施。
- 抽象类可保存共享状态和模板流程，但 Java 只能单继承。
- 接口可以有默认方法、静态方法和私有辅助方法，但不要把接口演化成状态复杂的基类。
- 业务中优先依赖接口，但不是每个类都机械创建接口；接口应对应可替换边界。

## 八、访问控制与模块边界

| 修饰符 | 同类 | 同包 | 子类跨包 | 其他包 |
|---|---:|---:|---:|---:|
| private | 是 | 否 | 否 | 否 |
| 默认 | 是 | 是 | 否 | 否 |
| protected | 是 | 是 | 是（受继承语义限制） | 否 |
| public | 是 | 是 | 是 | 是 |

最小可见性原则：先 private，再按真实协作边界放宽。包不是随意分类名称，而应体现模块内聚。

## 九、equals 与 hashCode 契约

- 相等对象必须有相同 hashCode。
- hashCode 相同不代表 equals 相等。
- 放入 HashMap/HashSet 后，不要修改参与 equals/hashCode 的字段，否则对象可能“留在桶里却查不到”。
- 实体是否按数据库 ID 相等要结合 ID 生成时机；DTO/值对象通常更适合按全部业务值比较。

## 十、不可变对象

常见做法：字段 private final、构造时校验、不提供修改方法、对可变成员防御性复制。

优势：状态容易推理、天然更适合共享、可安全作为 Map Key。注意 `final` 只保证引用不重新赋值，不保证引用对象内部不可变。

## 十一、static、final 与初始化顺序

- static 成员属于类；不要通过 static 共享可变业务状态。
- final 变量只能赋值一次；final 方法不能重写；final 类不能继承。
- 类初始化大致先父类静态，再子类静态；创建对象时先父类实例初始化/构造，再子类。
- 常量应同时具备稳定语义，而不只是写成 `public static final`。

## 十二、Record、Enum 与密封类

- Record 适合透明数据载体，自动提供访问器、equals/hashCode/toString；它不是无条件替代领域实体。
- Enum 是类型安全的有限集合，可封装行为；比字符串状态更能约束合法值。
- sealed class/interface 可以限制允许的子类型，适合封闭状态模型；仍需考虑框架代理和序列化兼容性。

## 十三、容易答错

- “Java 对象按引用传递”——错误，传递的是引用值副本。
- “final 对象不可变”——错误，只是引用不能重新赋值。
- “接口一定比抽象类好”——没有绝对优劣，取决于能力契约还是共享模板。
- “String 拼接一定产生很多对象”——取决于常量折叠、编译器优化和运行路径。
- “equals 相同和 hashCode 相同等价”——只有 equals 相同必须推出 hashCode 相同。
