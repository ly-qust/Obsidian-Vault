# Java 工程规范、测试、构建与发布

## 一句话结论

大厂后端不仅要“写得出功能”，还要让代码可构建、可测试、可审查、可灰度、可回滚和可观测。

## 一、项目结构与依赖方向

推荐按业务能力或清晰分层组织，核心原则是依赖从外向内可控：

```text
接口适配层 → 应用编排层 → 领域规则
基础设施层实现数据库、缓存、消息等端口
```

避免：Controller 调 Mapper、工具类堆业务、不同模块循环依赖、公共模块变成垃圾桶。

## 二、Maven 生命周期

常用阶段：validate → compile → test → package → verify → install → deploy。

- 生命周期阶段有顺序，插件 goal 才执行具体工作。
- `mvn package` 会执行前置阶段；不要把命令当互不相关动作。
- Wrapper 固定 Maven 版本，CI 和本地尽量一致。

## 三、依赖管理

- `dependencyManagement` 管版本，不会自动引入依赖。
- BOM 统一一组兼容版本。
- 传递依赖可能产生版本冲突，使用 dependency tree 查看来源。
- scope：compile、provided、runtime、test 等影响编译与运行 classpath。
- 不随意排除依赖；先确认谁需要它以及运行期影响。

版本冲突典型表现：`NoSuchMethodError`、`ClassNotFoundException`、行为不一致。排查 classpath 和最终构建产物，不只看 IDE。

## 四、单元测试

单元测试聚焦一个行为，依赖尽量使用测试替身，速度快、定位清晰。

AAA：Arrange 准备、Act 执行、Assert 验证。

不要只验证“方法被调用”，优先验证业务结果和状态不变量。Mock 过多说明对象职责可能过于耦合。

## 五、集成测试

验证数据库映射、事务、序列化、Spring 配置等真实协作。

- Repository/Mapper 测试使用真实数据库语义更可靠。
- 测试事务自动回滚可能掩盖提交后事件、约束和锁问题。
- 测试数据应独立、可重复，不依赖执行顺序。
- 外部服务使用 WireMock/MockWebServer 或测试环境契约，关键数据库/中间件可使用容器化测试。

## 六、测试金字塔

```text
少量端到端：验证关键用户链
适量集成：验证框架与基础设施
大量单元：验证业务规则和边界
```

覆盖率不是质量本身。优先覆盖状态机、金额、幂等、并发冲突、重试和异常路径。

## 七、并发测试

- 使用 CountDownLatch/Barrier 同时起跑，增加冲突概率。
- 断言最终不变量，如库存不负、只生成一张券。
- 重复执行并收集失败种子。
- 本地并发测试不能证明分布式绝对正确，数据库约束和故障实验仍需验证。

## 八、代码审查清单

- 输入是否校验，错误是否稳定。
- 是否有 SQL 注入、越权、敏感日志。
- 事务边界和异常处理是否正确。
- 查询是否 N+1、全表扫描、无界返回。
- 线程池/队列/缓存是否有上限。
- 重试是否幂等、是否设置超时。
- 资源是否关闭，日志是否包含 trace_id。
- 新配置是否有默认值、校验和文档。

## 九、日志规范

- 使用参数化日志，不手动字符串拼接昂贵对象。
- ERROR 表示需要关注的失败，不把可预期校验失败全部打 ERROR。
- 异常日志保留堆栈和业务上下文，但脱敏。
- 不在每层重复记录同一异常。
- 关键状态迁移记录业务 ID、前后状态、操作者和 trace_id。

## 十、静态检查与格式化

编译警告、SpotBugs/PMD/Checkstyle、依赖漏洞扫描、格式化工具可前移缺陷。规则要结合项目，避免只追求“零警告”而忽略真实风险。

## 十一、CI/CD

典型流水线：

```text
拉取代码
→ 编译/静态检查
→ 单元测试
→ 集成测试
→ 构建不可变制品
→ 漏洞/镜像扫描
→ 部署测试环境
→ 冒烟/契约测试
→ 灰度生产
→ 指标观察
→ 全量或回滚
```

同一 commit 应生成同一可追溯制品，不在不同环境重新手工打包。

## 十二、灰度与回滚

- 数据库变更优先向前/向后兼容：先加字段/双写，再迁移读，最后删除旧字段。
- 应用回滚不一定能回滚数据结构和已发送消息。
- Feature Flag 可控制功能，但需要权限、过期清理和审计。
- 灰度看错误率、P99、资源和业务指标，不只看服务是否启动。

## 十三、配置与密钥

- 配置分环境，敏感信息通过安全配置系统/环境注入。
- 日志和异常不得输出密钥。
- 配置变更应审计、可回滚并有校验。
- Feature 配置与基础设施参数分开治理。
