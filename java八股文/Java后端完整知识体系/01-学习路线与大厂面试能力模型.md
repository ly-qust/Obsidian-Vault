# 学习路线与大厂面试能力模型

## 一句话结论

大厂 Java 后端面试不是把名词背全，而是验证你能否从代码语义一路推到运行时、数据一致性、系统容量和故障定位。

## 一、六层能力模型

### 1. 语言表达层

必须熟练：基本类型、对象、方法调用、继承与多态、异常、泛型、集合、Lambda、Stream。

达标标准：看到一段代码，能判断编译结果、运行结果、对象关系、异常路径和复杂度。

### 2. 运行时层

必须掌握：JMM、线程、锁、线程池、虚拟线程、JVM 内存、类加载、GC、IO 和网络。

达标标准：能解释代码为什么线程不安全、为什么慢、为什么 OOM、为什么 CPU 高。

### 3. 框架层

必须掌握：Spring IOC、Bean 生命周期、AOP 代理、声明式事务、Spring MVC 请求链、Boot 自动配置、Security 基本链路、MyBatis Mapper 执行链。

达标标准：能从 HTTP 请求讲到 Controller、Service、Mapper、数据库，并指出代理和事务边界。

### 4. 数据与中间件层

必须掌握：MySQL 索引/事务/锁，Redis 缓存/分布式锁，RabbitMQ 确认/重试/死信/幂等。

达标标准：能解释缓存和数据库为什么不可能天然原子、消息为什么会重复、最终一致性靠什么闭环。

### 5. 工程与稳定性层

必须掌握：参数校验、日志、trace_id、指标、超时、重试、限流、熔断、降级、线程池隔离、连接池、Linux/网络排障。

达标标准：给一个“接口变慢/消息积压/CPU 高”的问题，能按证据顺序排查。

### 6. 项目与系统设计层

必须掌握：业务主链、数据模型、并发冲突、失败窗口、容量假设、技术取舍和演进方案。

达标标准：不按代码目录念项目，而是讲“问题 → 方案 → 证据 → 风险 → 改进”。

## 二、推荐学习顺序

```text
Java语法和OOP
→ 泛型/异常/反射/注解
→ 集合/数据结构/算法
→ JMM/锁/线程池
→ JVM/GC/IO/网络
→ Spring IOC/MVC/AOP/事务
→ JDBC/MyBatis/工程测试与构建
→ MySQL/Redis/RabbitMQ
→ 分布式一致性与稳定性
→ 项目串联与系统设计
```

原因：后面的每一层都依赖前面的抽象。没有代理和线程基础，很难真正理解事务失效；没有事务和唯一约束，很难回答幂等；没有网络和线程池，很难排查接口超时。

## 三、每个知识点的五次学习法

1. **定义**：它是什么，解决什么问题。
2. **机制**：核心对象、状态、数据结构或调用链。
3. **代码**：能写最小正确示例。
4. **边界**：什么时候不适用，常见误区是什么。
5. **项目**：SmartRenew 哪里用到，证据是什么。

例如学习事务：

```text
定义：一组操作作为逻辑工作单元。
机制：连接、事务管理器、代理、提交/回滚。
代码：@Transactional + 受检/非受检异常边界。
边界：自调用、非代理对象、异常被吞、跨库跨MQ。
项目：申请提交和Outbox同库事务。
```

## 四、面试深度分级

| 级别 | 表现 | 示例 |
|---|---|---|
| L1 记忆 | 只能背定义 | “HashMap 底层是数组加链表红黑树” |
| L2 机制 | 能讲执行过程 | put 如何定位桶、碰撞、扩容 |
| L3 边界 | 能讲失效场景 | 并发 put、可变 Key、hashCode 契约 |
| L4 工程 | 能落到选型和监控 | 并发场景选 CHM，容量预估与热点问题 |
| L5 设计 | 能串联系统取舍 | 本地缓存、Redis、数据库多级一致性 |

目标：P0 高频题至少达到 L3，项目相关题达到 L4，系统设计主链达到 L4～L5。

## 七、大厂面试常见评价点

- 术语准确，不用“绝对不会”“完全保证”等错误表达。
- 知道数据结构和复杂度，也知道并发、内存和下游边界。
- 能把单机机制扩展到分布式失败窗口。
- 项目数据和性能指标有来源，不编造 QPS、延迟和提升倍数。
- 排障先找证据，再改参数；不靠重启和“加机器”结束回答。
