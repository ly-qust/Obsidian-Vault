# 数据结构、算法与手写代码

## 一句话结论

算法面试考察把问题抽象成数据结构、维持不变量并写出可验证代码的能力；Java 后端候选人至少要稳定掌握数组、链表、哈希、树、堆、图和常用算法模板。

## 一、复杂度

- 时间复杂度描述输入规模增长时操作次数的数量级。
- 空间复杂度包含额外数据结构、递归栈等。
- 均摊复杂度用于扩容数组等“偶尔昂贵、多数便宜”的操作。
- 最坏、平均、期望复杂度必须区分，例如 HashMap 平均 O(1) 依赖 hash 分布。

常见增长：O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2^n)。

## 二、数组与字符串

高频模型：

- 双指针：有序数组、回文、原地去重。
- 滑动窗口：最长/最短连续子数组、字符频率。
- 前缀和：区间和、和为 K 的子数组。
- 差分：批量区间更新。
- 单调栈：下一个更大元素、柱状图。

滑动窗口不只是模板；必须说明窗口内维护什么不变量、何时扩张、何时收缩。

## 三、链表

必会：反转、快慢指针、环检测、合并、删除倒数第 K、相交链表。

手写反转：

```java
ListNode reverse(ListNode head) {
    ListNode prev = null;
    ListNode cur = head;
    while (cur != null) {
        ListNode next = cur.next;
        cur.next = prev;
        prev = cur;
        cur = next;
    }
    return prev;
}
```

面试要主动处理 null、单节点和环等边界。

## 四、栈、队列与 Deque

- 括号匹配、表达式、路径化简使用栈。
- BFS 使用队列。
- 单调队列解决滑动窗口最大值。
- Java 中优先 `ArrayDeque` 实现栈/队列，不使用遗留 Stack。

## 五、哈希

哈希用于快速判重、计数、索引和前缀状态映射。

典型题：两数之和、字母异位、最长连续序列、LRU、前缀和计数。

设计 Key 时遵守 equals/hashCode；使用可变对象 Key 会让算法和业务代码都出现难查错误。

## 六、二叉树与 BST

遍历：

- 前序：根左右，适合复制/序列化结构。
- 中序：左根右，BST 得到有序序列。
- 后序：左右根，适合汇总子树信息。
- 层序：BFS，适合层级和最短层数。

递归题先定义函数语义，例如“返回以当前节点为根的高度”，再由左右子树组合，避免边写边猜。

BST 查询平均与树高相关；退化链表时为 O(n)。平衡树通过旋转控制高度。

## 七、堆与 Top K

PriorityQueue 默认小根堆。

- 求最大 K 个：维护大小 K 的小根堆。
- 多路归并：堆保存每一路当前最小元素。
- 实时中位数：大根堆 + 小根堆维护两半。

比较器不要用 `b - a`，可能溢出；使用 `Integer.compare(b, a)`。

## 八、图

表示：邻接表适合稀疏图，邻接矩阵适合稠密图和 O(1) 边判断。

- BFS：无权图最短边数、层级扩散。
- DFS：连通分量、路径搜索、回溯。
- 拓扑排序：有向无环依赖；入度法可检测环。
- Dijkstra：非负权最短路。
- 并查集：动态连通性。

业务映射：任务依赖、课程顺序、服务依赖环、组织关系、风控关系网。

## 九、排序与查找

| 算法 | 平均 | 最坏 | 稳定 | 特点 |
|---|---:|---:|---:|---|
| 快速排序 | O(n log n) | O(n²) | 否 | 原地、常数小，需选枢轴 |
| 归并排序 | O(n log n) | O(n log n) | 是 | 需额外空间，适合外部排序思想 |
| 堆排序 | O(n log n) | O(n log n) | 否 | 原地，缓存局部性一般 |

二分查找最容易错的是边界。先统一闭区间 `[left,right]` 或左闭右开 `[left,right)`，循环条件和更新规则必须匹配。

## 十、回溯

模板：选择 → 递归 → 撤销选择。适合排列、组合、子集、棋盘搜索。

优化：排序后剪枝、提前验证、位图状态。必须分析指数复杂度，不能把剪枝说成改变最坏复杂度保证。

## 十一、动态规划

四步：

1. 定义状态含义。
2. 写状态转移。
3. 确定初始化。
4. 确定遍历顺序和答案位置。

高频：背包、最长递增子序列、最长公共子序列、路径计数、区间 DP。

如果无法定义“dp[i] 表示什么”，通常还没有真正理解题目。

## 十二、贪心

每步取局部最优，并需要交换论证或结构证明能得到全局最优。看到“最大/最小”不能自动使用贪心。

典型：区间调度、跳跃、部分资源分配。不能证明时考虑 DP 或搜索。

## 十三、LRU 手写

O(1) LRU = HashMap + 双向链表：Map 定位节点，链表维护最近使用顺序。

必须处理：更新已有 Key、容量为 0、移动头部、淘汰尾部、链表断链。面试中先定义哨兵节点可减少边界分支。

## 十四、生产代码与算法题差异

- 算法题输入常在内存，生产系统还要考虑 IO、并发、超时和数据规模。
- 不要为追求 O(1) 引入巨大内存；复杂度与常数、局部性共同决定性能。
- 数据库擅长集合运算和索引，不要全量拉到 Java 再排序过滤。
- 清晰、可测试的 O(n log n) 往往优于脆弱的“聪明”代码。

## 十五、手写代码验收

至少能独立写：

- 单例（说明不一定需要手写）。
- LRU。
- 生产者消费者。
- 两线程交替打印。
- 限流器简化版。
- 线程安全计数。
- 二分查找边界。
- 链表反转与环检测。
- 二叉树遍历。
- Top K。

写完主动给复杂度、空输入、溢出、并发和测试样例。

## 十六、刷题路线

```text
数组/字符串 20题
→ 链表/栈/队列 15题
→ 哈希/双指针/滑窗 20题
→ 树/堆 25题
→ 图/并查集 10题
→ 回溯/DP 25题
→ 每周2次限时模拟
```

错题记录“为何没想到、哪个不变量没维护”，不要只收藏答案。
