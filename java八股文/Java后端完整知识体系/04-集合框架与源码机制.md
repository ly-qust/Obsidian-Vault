# 集合框架与源码机制

## 一句话结论

集合选型先看数据语义，再看读写模式、复杂度、顺序、并发和内存；背底层结构但不会选型，面试仍不合格。

## 一、集合体系

```text
Iterable
└─ Collection
   ├─ List：有序、可重复、按索引
   ├─ Set：元素不重复
   └─ Queue/Deque：队列、双端队列、优先队列

Map：键值映射，不继承 Collection
```

## 二、List 选型

| 实现 | 底层 | 典型优势 | 主要风险 |
|---|---|---|---|
| ArrayList | 动态数组 | 随机访问快、缓存局部性好 | 中间插删搬移；扩容复制 |
| LinkedList | 双向链表 | 已持有节点位置时插删方便 | 按索引遍历慢、节点内存大、局部性差 |
| CopyOnWriteArrayList | 写时复制数组 | 读无锁快照，遍历稳定 | 写成本高、内存峰值、只能最终看到新数据 |

### ArrayList 扩容

- 维护元素数组和逻辑 size；容量不足时创建更大数组并复制。
- 常见 OpenJDK 实现按约 1.5 倍扩容，但这是实现细节，不是 List 接口契约。
- 已知大致元素数时设置初始容量，减少复制和临时数组。
- `subList` 常是原列表的视图，结构修改可能导致联动或并发修改异常；跨层返回时谨慎。

### 为什么多数场景 ArrayList 优先

业务往往需要遍历和随机访问；ArrayList 连续内存引用有更好缓存局部性。LinkedList 的“插入 O(1)”前提是已经定位节点，若先按索引查找仍是 O(n)。

## 三、Set 与去重

- HashSet 基于 HashMap 的键实现，依赖 equals/hashCode。
- LinkedHashSet 在哈希结构外维护顺序，适合去重且保留插入顺序。
- TreeSet 基于有序树，按自然顺序或 Comparator 排序，操作通常 O(log n)。
- 比较器必须与相等语义协调，否则 TreeSet 可能把 compare 为 0 的不同对象视为同一元素。

## 四、HashMap 核心链路

```text
key.hashCode
→ 扰动/传播高位信息
→ (table.length - 1) & hash 定位桶
→ 空桶直接插入
→ 冲突时比较 hash + equals
→ 链表过长且容量足够时树化
→ size 超过 threshold 后扩容
```

### 为什么容量常为 2 的幂

可以用位运算替代取模，并在扩容为 2 倍时通过旧 hash 的一个高位判断元素留在原索引还是移动到 `oldIndex + oldCapacity`。

### 常见实现参数

- 默认初始容量常见为 16。
- 默认负载因子常见为 0.75。
- 链表树化阈值常见为 8，退化阈值常见为 6。
- 桶树化前通常要求表容量至少 64，否则优先扩容。

这些是常见 OpenJDK 实现细节，不应说成所有 Java 实现永恒不变的规范。

### put 的关键判断

1. 表未初始化则初始化。
2. 桶为空，放入新节点。
3. Key 已存在，替换 Value 并返回旧值。
4. 冲突则进入链表或红黑树查找/插入。
5. 插入新 Key 后 size 增加，超过阈值触发 resize。

### 为什么 HashMap 非线程安全

并发读写缺少完整同步；可能出现覆盖、丢失更新、读到不一致结构。即使现代实现避免了早期扩容死循环，也不能因此说它线程安全。

## 五、equals/hashCode 与 Key 设计

- 相等对象必须返回相同 hashCode。
- Key 放入 Map 后应保持参与比较的字段不变。
- 业务实体使用数据库 ID 做 Key 时，要考虑持久化前后 ID 从 null 变为非 null 的变化。
- 组合 Key 可以用不可变 record，减少拼接字符串和分隔符碰撞。

## 六、LinkedHashMap 与 LRU

LinkedHashMap 维护双向链表，可按插入顺序或访问顺序迭代。重写 `removeEldestEntry` 可实现简单 LRU，但它本身不线程安全，也缺少复杂淘汰、统计和并发优化；生产缓存优先使用 Caffeine。

## 七、TreeMap

- 基于红黑树，Key 有序，查找/插入/删除通常 O(log n)。
- 适合范围查询、最小/最大、前驱/后继。
- Comparator 必须传递、一致并避免整数相减导致溢出；使用 `Integer.compare`。
- HashMap 追求平均 O(1)，TreeMap 提供顺序语义，不是谁绝对更快。

## 八、ConcurrentHashMap

现代常见实现以数组、链表/红黑树、CAS 与桶级同步协作，避免对整张表加一把全局锁。

关键边界：

- 不允许 null Key/Value，避免并发读取时无法区分“没有映射”和“映射值为 null”。
- 单个 `get`/`put` 线程安全，不代表多个调用组成的业务流程原子。
- 复合更新使用 `compute`、`computeIfAbsent`、`merge` 等原子方法，但映射函数应短小，避免递归更新、阻塞 IO 和副作用。
- `size()` 在高并发变化中更适合统计近似视角，不应作为跨操作强一致判断。

```java
counts.merge(key, 1L, Long::sum);
```

## 九、并发集合选择

| 需求 | 推荐 | 原因 |
|---|---|---|
| 并发 Key-Value | ConcurrentHashMap | 分散竞争、复合原子 API |
| 读多写极少列表 | CopyOnWriteArrayList | 读快照稳定 |
| 生产者消费者 | BlockingQueue | 阻塞、容量和背压语义 |
| 高吞吐无界队列 | ConcurrentLinkedQueue | 非阻塞算法，但无容量保护 |
| 计数热点 | LongAdder | 分散高竞争更新，读取不是事务快照 |

## 十、Queue 与 Deque

- `ArrayDeque` 通常优于 Stack，支持栈和双端队列语义，不允许 null。
- `PriorityQueue` 按优先级取堆顶，不保证遍历整体有序。
- `ArrayBlockingQueue` 有界，适合显式容量控制。
- `LinkedBlockingQueue` 可设容量；不设置时容量很大，可能积压占内存。
- `SynchronousQueue` 不存储元素，每次 put 必须与 take 直接交接。
- `DelayQueue` 适合进程内延迟任务，但关键任务仍需持久化。

## 十一、迭代器与 fail-fast

普通集合迭代时检测结构修改，可能抛 `ConcurrentModificationException`。它是尽力发现 bug 的机制，不是并发正确性保证。

正确删除：使用 Iterator 自己的 `remove`，或使用 `removeIf`。并发修改需求应选择并发集合或重新设计所有权。

## 十二、复杂度与真实成本

| 操作 | 平均复杂度 | 真实成本补充 |
|---|---:|---|
| ArrayList get | O(1) | 边界检查、缓存友好 |
| ArrayList 中间插入 | O(n) | 数组搬移 |
| HashMap get/put | 平均 O(1) | hash、equals、冲突、扩容 |
| TreeMap get/put | O(log n) | 比较器与节点跳转 |
| LinkedList 按索引 get | O(n) | 指针追踪、缓存不友好 |

复杂度相同不代表性能相同；对象分配、缓存局部性、锁竞争和数据分布同样重要。
