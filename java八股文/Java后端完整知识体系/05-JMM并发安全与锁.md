# JMM、并发安全与锁

## 一句话结论

并发问题来自多个执行单元对共享状态的交错访问；正确性必须同时处理可见性、原子性、有序性和业务不变量。

> [!note] 主解释位置
> 竞态、临界区、互斥/同步、Condition、Semaphore、CAS/ABA 和死锁的跨层因果链统一见 [[操作系统面试精炼笔记/05-同步互斥信号量与死锁]]。本文只保留 JMM、happens-before、Java 工具选型和 JVM 内排障。

## 一、进程、平台线程与任务

- 进程拥有独立地址空间和资源边界。
- Java 平台线程通常对应操作系统线程，由 OS 调度。
- 任务是要执行的工作，不应与承载任务的线程绑定。
- Java 21 虚拟线程由 JVM 调度到平台载体线程，详细见下一篇。

OS 关联：[[操作系统面试精炼笔记/01-进程线程与上下文切换]]。

## 二、Java 内存模型解决什么

JMM 定义线程间共享变量读写的可见性和有序性规则，让代码不依赖具体 CPU 缓存与编译器实现。

三类问题：

- **可见性**：一个线程写入，另一个何时看见。
- **原子性**：操作是否能被拆分和交错。
- **有序性**：编译器和 CPU 可在不破坏单线程语义的前提下重排。

`i++` 包含读取、计算、写回，不因变量是 volatile 就整体原子。

## 三、happens-before

happens-before 不是物理时间先后，而是 JMM 对可见性与排序的保证。

高频规则：

- 同一线程中前面的操作先于后面的操作。
- 解锁先于后续对同一锁的加锁。
- volatile 写先于后续对同一变量的 volatile 读。
- `Thread.start()` 前的操作先于新线程中的操作。
- 线程中的操作先于其他线程成功 `join()` 返回。
- 规则具有传递性。

安全发布可通过锁、volatile、静态初始化、线程安全容器等建立 happens-before。

## 四、volatile

volatile 适合：状态标志、安全发布、读写本身就是完整操作且不依赖其他变量的不变量。

它提供：

- 对该变量读写的可见性。
- 相关内存操作的排序约束。
- 单次读写的原子性。

它不提供：

- `count++` 的复合原子性。
- 多个变量共同不变量。
- 互斥执行。

## 五、synchronized

synchronized 同时提供互斥、可见性和锁语义，可用于实例方法、静态方法和显式代码块。

- 实例方法锁当前对象。
- 静态方法锁 Class 对象。
- 锁对象必须稳定，不能每次创建新对象。
- 不要锁字符串常量、包装缓存对象等可能被无关代码共享的对象。
- 临界区只放必须原子执行的共享状态逻辑，避免包含慢 IO。

## 六、ReentrantLock

相对 synchronized，它提供：

- `tryLock` 非阻塞尝试。
- 可超时、可中断获取锁。
- 公平锁选项。
- 多个 Condition 等待队列。

必须在 finally 中解锁：

```java
lock.lock();
try {
    updateState();
} finally {
    lock.unlock();
}
```

选择原则：普通互斥优先 synchronized；确实需要超时、中断、多条件或显式锁编排时使用 ReentrantLock。

## 七、CAS 与原子类在 Java 中的选型

CAS/ABA 和“单个 Atomic 操作不等于多步业务原子”的主解释见 [[操作系统面试精炼笔记/05-同步互斥信号量与死锁]]。

- AtomicInteger/AtomicLong：单变量原子更新。
- AtomicReference：原子替换对象引用，不自动保证对象内部字段组合不变量。
- AtomicStampedReference：业务确实关心 A→B→A 历史时引入版本戳。
- LongAdder：分散热点以提高高竞争计数吞吐，但 sum() 不是跨所有更新的事务快照，不适合强一致余额。
- 多字段或“检查 + 更新”业务：优先把条件编码进单次 CAS 循环，无法表达时用锁或数据库条件更新。

## 八、AQS

AbstractQueuedSynchronizer 用一个同步状态和等待队列支持锁、信号量、闭锁等同步器。

理解主线：

```text
尝试获取同步状态
→ 失败则进入等待队列
→ 挂起/被唤醒
→ 前驱释放后再次竞争
```

面试不需要默写所有源码，但要知道 ReentrantLock、Semaphore、CountDownLatch 等共享类似同步基础设施，独占/共享模式语义不同。

## 九、并发工具

| 工具 | 作用 | 不解决什么 |
|---|---|---|
| CountDownLatch | 等待一组事件完成 | 不能重置复用 |
| CyclicBarrier | 多线程到达屏障后一起继续 | 屏障动作失败会破坏本轮 |
| Semaphore | 限制同时进入的许可数 | 不等于分布式限流 |
| Phaser | 多阶段动态参与者协作 | 使用复杂，需管理阶段终止 |
| BlockingQueue | 生产消费和容量背压 | 关键任务掉电持久化 |

## 十、ThreadLocal

ThreadLocal 提供“每个线程一份值”，常用于请求上下文、事务资源绑定等。

线程池风险：线程会复用，若不 remove，旧请求数据可能泄漏到后续任务并延长对象生命周期。

```java
try {
    CONTEXT.set(ctx);
    handle();
} finally {
    CONTEXT.remove();
}
```

ThreadLocal 不是并发共享工具，也不自动跨线程传播。异步任务需要显式传递上下文。

## 十一、Java 死锁排查

死锁四条件、预防/避免/检测/恢复及活锁/饥饿区别见 [[操作系统面试精炼笔记/05-同步互斥信号量与死锁]]。

Java 工程只记操作顺序：先保存 thread dump → 找 BLOCKED/WAITING 与持锁者 → 画等待环 → 对照代码中的嵌套加锁和持锁慢 IO → 修正统一锁顺序、超时与释放路径。重启只能恢复服务，不能消除根因。

## 十二、线程安全层次

- 无状态对象通常易于并发共享。
- 不可变对象通过不变状态降低同步需求。
- 线程封闭让状态只归一个线程所有。
- 同步保护共享可变状态。
- 数据库唯一约束/条件更新保护跨 JVM 业务不变量。

Java 锁只能保护当前进程内共享内存，不能直接保护多实例之间的数据库业务。
