# JVM 内存、GC 与排查

[[02-并发工具选型|上一篇：并发]] · [[00-Java后端面试知识地图|知识地图]] · [[04-Spring Boot-AOP与事务|下一篇：Spring]]

## 1. 运行时数据区

| 归属 | 区域 | 作用 |
|---|---|---|
| 线程私有 | 程序计数器 | 当前线程执行位置 |
| 线程私有 | Java虚拟机栈 | Java方法栈帧：局部变量、操作数栈等 |
| 线程私有 | 本地方法栈 | Native方法调用支持 |
| 线程共享 | 堆 | 对象和数组的主要分配区域 |
| 线程共享 | 方法区（规范概念） | 类元数据、运行时常量池等 |

HotSpot 从 JDK 8 起常用 Metaspace 实现方法区的主要类元数据存储，并使用本地内存。不要把“方法区”和“元空间”在所有 JVM 上说成完全同一个规范概念。

## 2. 对象创建主链

```text
遇到new
→ 检查类是否已加载、链接、初始化
→ 在堆中分配内存
→ 零值初始化
→ 设置对象头
→ 执行实例字段初始化和构造器
→ 引用保存到局部变量/字段等位置
```

不要说“把对象复制给栈中的引用”；对象通常在堆中，变量保存的是引用值，而且引用也可能位于对象字段、静态字段等位置。

## 3. GC Roots 与可达性

常见 Roots：

- 活跃线程栈帧中的局部引用；
- 类的静态字段引用；
- 运行时常量相关引用；
- JNI 本地引用；
- JVM 内部引用、活跃线程等也可能作为根。

从 Roots 能到达的对象通常保留；不可达对象才具备被回收资格，不等于一定立即回收。

## 4. 三种基础算法

| 算法 | 特点 | 适合 |
|---|---|---|
| 标记-清除 | 不移动存活对象；会产生碎片 | 移动成本高或特定收集阶段 |
| 标记-复制 | 复制存活对象；无外部碎片，但需要额外空间 | 存活对象少，如年轻代 |
| 标记-整理 | 存活对象向一端移动；减少碎片 | 存活对象较多，如老年代思路 |

现代收集器通常组合使用算法，不能只按三种算法直接等同具体收集器。

## 5. 堆 OOM 与 StackOverflowError

堆 OOM 不只来自“循环创建对象”：可能是内存泄漏、真实数据量超过堆容量、超大对象、缓存无上限、GC效率低或堆参数不合适。StackOverflowError 常见于无限递归、递归过深或单个栈帧过大。

## 6. 初步排查

### 堆 OOM

```text
确认时间点与错误日志
→ 保留Heap Dump（如配置-XX:+HeapDumpOnOutOfMemoryError）
→ 看GC日志：频率、停顿、回收后占用
→ MAT/JProfiler分析大对象、支配树、GC Root引用链
→ 区分泄漏与容量不足
→ 修代码/限制缓存/分批处理，再评估堆参数
```

### StackOverflowError

```text
查看异常栈
→ 找重复方法与递归终止条件
→ 检查循环调用/AOP代理链
→ 修正递归或改为迭代
→ 只有业务递归确实合理时才谨慎评估-Xss
```

## 7. 60 秒回答

> JVM 运行时区域中，程序计数器、Java 虚拟机栈和本地方法栈线程私有，堆和方法区逻辑上线程共享；HotSpot 常用元空间承载类元数据。堆 OOM 要结合 GC 日志和 Heap Dump 区分内存泄漏与容量不足，通过大对象、支配树和 GC Root 引用链定位。StackOverflowError 则优先看重复调用栈和递归终止条件。GC 可达性从栈局部引用、静态引用、常量引用、JNI 引用等 Roots 出发，不可达对象才具备回收资格。
