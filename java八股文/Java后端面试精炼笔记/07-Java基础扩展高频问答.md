# Java 基础扩展高频问答

## 使用范围

这里只保留异常、泛型、IO、Stream、反射和注解的面试主干。完整课程、示例代码和学习过程回到文末 Reference。

## 一、异常

### 1. `Exception` 和 `Error` 有什么区别？

`Exception` 表示程序或外部环境中通常可以预期、处理或向上转交的问题；`Error` 通常表示 JVM 或运行环境的严重故障，例如 `OutOfMemoryError`。业务代码不应为了“兜底”而捕获所有 `Error`。

### 2. Checked Exception 和 RuntimeException 的区别？

除 `RuntimeException` 及其子类、`Error` 外，`Exception` 子类通常是 checked exception，编译器要求调用方捕获或声明。`RuntimeException` 不强制声明，常用于参数非法、状态错误等编程或业务边界问题；是否自定义 checked exception 要看调用方是否能恢复处理。

### 3. `throw` 和 `throws` 的区别？

`throw` 在方法体内主动抛出一个异常对象；`throws` 写在方法签名上，声明该方法可能把异常交给调用方。`throws` 不是处理异常，调用方仍需决定捕获、转换或继续向上抛出。

### 4. `finally` 一定会执行吗？

正常离开 `try` 或 `catch` 时通常会执行 `finally`，适合释放资源和清理状态。但 JVM 强制终止、进程崩溃等情况不能保证执行。不要在 `finally` 中 `return` 或覆盖原异常，否则会掩盖原结果。

### 5. 为什么推荐 try-with-resources？

实现 `AutoCloseable` 的资源可以由 try-with-resources 自动关闭，关闭顺序与声明顺序相反；如果主体和关闭过程都抛异常，后发生的关闭异常会作为 suppressed exception 关联到主体异常。它比手写 `finally` 更不容易遗漏关闭和原始异常。

### 6. 异常应该怎么处理才不会丢失上下文？

只捕获能够处理的异常；转换异常时保留 cause，例如 `throw new BizException("调用库存服务失败", e)`。日志要包含请求或业务标识，但不要记录密码、Token 等敏感信息，也不要用空 `catch` 或无上下文的 `printStackTrace()`。

### 7. 自定义业务异常要注意什么？

异常应表达可判断的业务失败原因，包含稳定的错误码和必要上下文；参数校验、资源不存在、状态不允许等可以区分处理。异常不能替代正常分支，也不能把所有异常都包装成“系统异常”而丢失可重试/不可重试边界。

## 二、泛型

### 8. 泛型解决什么问题？

泛型把类型约束前移到编译期，减少强制类型转换，并让集合、接口和方法在保持复用的同时保留类型信息。它主要提供编译期类型安全，不等于运行时保留完整的参数化类型。

### 9. 什么是类型擦除？

Java 泛型主要通过类型擦除实现兼容：编译后大多数参数化类型不会以普通运行时类型存在，编译器会在需要处插入转换。因此通常不能写 `new T()`、`List<String>.class`，也不能仅靠泛型参数重载两个方法。反射读取泛型签名是另一条元数据路径，不代表所有运行时检查都恢复了泛型类型。

### 10. `? extends T` 和 `? super T` 怎么选？

`? extends T` 表示某个未知的 `T` 子类型，适合读取为 `T`，通常不能安全写入具体对象；`? super T` 表示某个 `T` 的父类型，适合写入 `T`，读取时只能按 `Object` 使用。记忆为 PECS：Producer Extends，Consumer Super。

### 11. `List<String>` 为什么不是 `List<Object>` 的子类型？

如果允许这种替换，就能通过 `List<Object>` 向实际的 `List<String>` 放入非字符串对象，破坏类型安全。因此参数化类型默认保持不变；需要只读不同元素类型时使用 `List<?>`，需要生产/消费边界时使用通配符。

## 三、IO

### 12. 字节流和字符流怎么选？

图片、压缩包、音视频等二进制数据使用 `InputStream` / `OutputStream`；文本使用 `Reader` / `Writer`，并明确字符集。字符流不是“更高级的字节流”，它负责字符解码/编码，错误字符集会导致乱码。

### 13. 缓冲流解决什么问题？

`BufferedInputStream`、`BufferedReader` 等在用户态暂存数据，减少频繁的小块读写和系统调用次数。缓冲区不能改变磁盘、网络或下游本身的速度，仍需正确关闭资源并设置合适的超时。

### 14. BIO 和 NIO 的基本区别？

BIO 通常表现为一次读写操作可能阻塞当前线程；NIO 提供 `Buffer`、`Channel`、`Selector` 等抽象，可支持更灵活的缓冲和多路复用。`java.nio.file.Files` 的文件操作不等于自动非阻塞，不能把“NIO”简单等同于“完全异步”。

### 15. 文件操作的基本选择是什么？

现代 Java 代码通常优先使用 `Path` 和 `Files`，根据文件大小和处理方式选择一次性读取、流式读取或缓冲读取。大文件不要无条件 `readAllBytes()`；外部资源要设置超时、使用 try-with-resources，并处理权限、编码和部分读写边界。

## 四、Stream

### 16. Stream 和 Collection 的区别？

Collection 主要表示和管理数据；Stream 表示一次性的处理流水线，不负责存储数据。Stream 通常不能重复消费，适合表达过滤、映射、聚合等数据处理，不应把它当作可修改集合。

### 17. 中间操作和终止操作有什么区别？

`filter`、`map`、`sorted` 等是中间操作，通常惰性执行；`collect`、`reduce`、`forEach`、`count` 等是终止操作，触发流水线执行。复杂流水线要注意遍历次数、异常处理和副作用。

### 18. `map` 和 `flatMap` 怎么区分？

`map` 把一个元素映射成一个结果；`flatMap` 把一个元素映射成一个流并把多层流展开。例如订单映射订单项列表时，想得到一个扁平订单项流通常使用 `flatMap`。

### 19. 什么场景不适合滥用 Stream？

需要复杂分支、频繁修改外部状态、精细控制异常或追求最直观调试过程时，普通循环可能更清晰。并行流也不是默认优化方案，必须确认任务可拆分、无共享副作用，并用实际数据验证收益。

## 五、反射与注解

### 20. 反射是什么？Spring/MyBatis 为什么使用它？

反射允许程序在运行时读取类、方法、字段、构造器和注解等元数据，并进行调用或创建对象。Spring 可据此完成组件扫描、依赖注入和代理配合；MyBatis 可据此完成 Mapper、参数和结果映射。它带来灵活性，同时增加运行时检查和调试复杂度。

### 21. 反射的代价和边界是什么？

反射调用通常比直接调用更难被编译器静态检查，也可能受访问控制、模块边界和安全策略影响。核心热路径不应无依据地频繁反射；框架通常会缓存元数据或使用代理、字节码等方式降低重复成本。

### 22. 注解本身会执行逻辑吗？

不会。注解主要是附着在代码上的元数据；是否生效取决于编译器、注解处理器、框架扫描、反射或 AOP 等机制。`Retention` 决定保留到源码、字节码还是运行时，`Target` 限制可使用位置。看到 `@Transactional` 等注解时，要继续追问谁读取它、何时读取以及如何改变调用链。

## 30 秒回答

Java 基础扩展面试可以按“编译期约束、运行时机制、工程边界”回答：异常先区分可处理问题和 JVM 故障，资源用 try-with-resources 管理；泛型提供编译期类型安全，但通常会类型擦除；IO 按二进制/文本和数据规模选型，Stream 适合无副作用的数据流水线；反射和注解提供框架扩展能力，但真正产生行为的是 Spring、MyBatis、AOP 或处理器等读取机制。
