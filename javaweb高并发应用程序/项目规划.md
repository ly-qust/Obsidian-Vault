# 一、先定项目目标

这个项目不是普通 CRUD，而是一个**高并发资格审核 + 额度竞争 + 券发放 + AI解释问答**平台。

## 1. 核心价值

面向“家电/数码/电动自行车/手机等以旧换新补贴”活动场景，实现：

- 用户提交申请材料

- 高峰期并发抢占补贴额度
    
- 商户端核销补贴券
    
- 管理端查看额度池、审核结果、风控记录
    
- AI 助手解释规则、补材料建议、问答咨询

# 二、AI 开发流程总计划

项目周期建议：**5~6 周**

## 1.2 核心业务流程

你要把项目主线定成这 6 条：

### 流程 1：资格预检

用户输入基础信息，系统根据规则快速判断：

- 是否符合申请条件
    
- 可申请哪类补贴
    
- 预计补贴金额范围
    
- 还缺哪些材料
    

### 流程 2：正式申请

用户填写完整信息并上传材料：

- 身份信息
    
- 商品信息
    
- 发票/订单截图
    
- 回收旧机凭证
    

### 流程 3：异步审核

申请提交后：

- 先入库
    
- 发送 MQ 消息
    
- AI 做文本说明分析
    
- 系统规则引擎做资格判断
    
- 审核员必要时人工复核
    

### 流程 4：额度占用与发券

审核通过后：

- 竞争额度池
    
- Redis 预扣减
    
- DB 乐观锁最终扣减
    
- 发放电子补贴券
    

### 流程 5：商户核销

商户端核销券码：

- 校验券是否有效
    
- 校验是否已核销
    
- 校验使用时间
    
- 更新券状态
    

### 流程 6：AI 问答与解释

用户可提问：

- 我为什么审核失败？
    
- 我还差哪些材料？
    
- 哪种商品能申请？
    
- 活动规则是什么？

## 4.4 压测重点场景

建议至少做 3 组：

### 场景 1：资格预检高并发

1000 用户并发访问预检接口，观察：

- 平均响应时间
    
- Redis 命中率
    
- CPU 占用
    

### 场景 2：额度池竞争

300 并发用户同时申请同一类补贴额度，观察：

- 是否超发
    
- 是否重复发放
    
- 乐观锁冲突次数
    

### 场景 3：商户核销并发

100 商户并发核销同一批券，观察：

- 是否重复核销
    
- 状态是否一致
