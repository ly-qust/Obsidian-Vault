# 高频面试速记与自测

[[04-主从复制与高可用|上一篇：复制]] · [[00-MySQL面试知识地图|知识地图]]

> [!tip] 使用方法
> 先遮住答案口述 30～60 秒，再展开核对。回答结构：结论 → 机制 → 场景 → 边界。

## 1. 为什么 InnoDB 使用 B+Tree？

B+Tree 分支多、树高低，适合磁盘页；叶子节点有序连接，既支持等值查询，也支持范围和排序。实际物理 IO 次数还取决于 Buffer Pool，不能机械说固定三次 IO。

## 2. 聚簇索引与二级索引有什么区别？

聚簇索引叶子节点保存完整行，一张表一个；二级索引叶子节点主要保存索引列和主键。二级索引缺少查询列时，需要拿主键访问聚簇索引，这就是回表。

## 3. 什么是覆盖索引？

查询需要的列都能从一个索引中取得，通常不需要常规回表。`Using index` 常表示覆盖；`Using index condition` 是 ICP，仍可能回表。

## 4. 联合索引为什么有最左前缀？

`(a,b,c)` 先按 a 排序，a 相同再按 b、c。缺少左侧有序基础时，后续列通常不能直接精准定位；但优化器可能使用 skip scan，后续列也可能用于过滤或覆盖。

## 5. 范围条件后面的列是否完全失效？

不一定。后续列通常不能继续缩小扫描区间，但仍可能参与 ICP、过滤、排序或覆盖，最终看执行计划。

## 6. `key` 不为空为什么仍可能慢？

可能扫描范围过大、选择性差、回表太多、发生 filesort/temporary，或真正瓶颈是锁等待和 IO。必须结合 `rows`、`Extra` 和实际耗时。

## 7. EXPLAIN 和 EXPLAIN ANALYZE 有什么区别？

EXPLAIN 主要给优化器估算计划；EXPLAIN ANALYZE 会实际执行并返回真实行数、循环和耗时，因此生产环境需谨慎。

## 8. undo、redo、binlog 分别做什么？

undo 用于回滚和 MVCC；redo 用于 WAL 和 InnoDB 本机崩溃恢复；binlog 属于 Server 层，用于复制、归档和时间点恢复。

## 9. 为什么需要两阶段提交？

提交同时涉及 redo 和 binlog。通过 redo prepare、binlog、redo commit 协调状态，避免主库崩溃恢复结果与复制日志不一致。

## 10. RC 与 RR 的 Read View 有什么区别？

RC 每次普通一致性读通常创建新的 Read View；RR 第一次一致性读通常建立 Read View，后续复用。因此 RC 能看到其他事务新提交的数据，RR 的快照读通常保持稳定。

## 11. 快照读与当前读有什么区别？

普通 SELECT 在 RC/RR 下通常通过 MVCC 快照读，不加行锁；`FOR UPDATE`、`FOR SHARE`、UPDATE、DELETE 属于锁定读或当前读，需要读取当前数据并加锁。

## 12. RR 为什么还需要 `FOR UPDATE`？

RR 的快照只能保证读取历史视图稳定，不能自动保护“查询后再修改”的业务判断。`FOR UPDATE` 通过锁阻止其他事务并发修改相关记录或范围。

## 13. 记录锁、间隙锁、临键锁是什么？

记录锁锁索引记录；间隙锁锁索引之间的空隙，主要阻止插入；临键锁等于记录锁加前方间隙锁，用于 RR 下范围扫描防止插入幻影行。

## 14. 唯一索引等值未命中加什么锁？

RR 下没有具体记录可锁，通常锁目标值应该出现的间隙；RC 下普通搜索通常不使用间隙锁，外键和重复键检查等例外。

## 15. 锁等待与死锁有什么区别？

锁等待是单向等待，持锁事务结束后可以继续；死锁是等待关系形成环，InnoDB 会回滚一个事务。1205 常见于等待超时，1213 常见于死锁。

## 16. 怎样排查接口被数据库锁住？

先用 `data_lock_waits` 找等待者和阻塞者，再用 `data_locks` 看表、索引、模式与状态，结合 `SHOW FULL PROCESSLIST` 看 SQL；历史死锁用 `SHOW ENGINE INNODB STATUS`。

## 17. 怎样减少死锁？

按相同顺序访问数据、使用合适索引缩小锁范围、缩短事务、避免事务内远程调用，并在应用中对死锁重试整个事务。

## 18. 主从复制怎样工作？

主库写 binlog，dump 线程发送；从库 I/O 接收线程写 relay log，applier 线程重放。异步复制可能延迟，因此写后立刻读从库可能读不到新数据。
