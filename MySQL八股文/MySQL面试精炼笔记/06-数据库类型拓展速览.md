# 数据库类型拓展速览

[[00-MySQL面试知识地图|返回知识地图]]

> [!warning] 复习优先级较低
> 面试先掌握 MySQL/InnoDB 主线。本篇用于回答“为什么选关系型数据库、其他数据库适合什么场景”。

## 1. 关系型与非关系型

![[Pasted image 20260121094315.png|850]]

关系型数据库以表、约束、关系和 SQL 为核心，适合结构稳定、事务与一致性要求较高的业务，例如订单、账户和库存。

![[Pasted image 20260121094434.png|700]]

NoSQL 是 Not Only SQL，通常针对特定数据模型和访问模式优化，不表示完全没有结构或不支持查询。

## 2. 常见关系型产品

![[Pasted image 20260121094339.png|850]]

选择数据库应看事务、一致性、生态、运维能力、数据模型和访问模式，不只看“功能多不多”。

## 3. 文档数据库

![[Pasted image 20260121094813.png|800]]

以 JSON/BSON 等文档保存半结构化数据，适合字段灵活、聚合对象整体读写的场景。

## 4. 搜索引擎数据库

![[Pasted image 20260121095233.png|800]]

通过倒排索引支持全文检索、分词和相关性排序。它适合搜索，不应默认替代交易数据库作为唯一事实源。

## 5. 向量数据库

![[Pasted image 20260121095355.png|750]]

保存向量表示并进行相似度搜索，常用于语义检索、推荐和 RAG；结果通常是近似相似，不等同于关系型精确匹配。

## 6. 图数据库

![[Pasted image 20260121095950.png|700]]

以节点和边表达复杂关系，适合社交网络、路径查询、知识图谱和风控关系分析。

## 7. 时序数据库

![[Pasted image 20260121100847.png|800]]

围绕时间戳组织指标数据，擅长高吞吐写入、时间窗口聚合和降采样，常用于监控与 IoT。

## 8. 列式数据库

![[Pasted image 20260121101036.png|800]]

按列组织和压缩数据，适合扫描少量列的大规模分析；传统行式数据库更适合频繁点查和事务更新。

## 面试一句话

> MySQL 适合事务型结构化数据并作为业务事实源；Redis 适合缓存和高吞吐键值访问；Elasticsearch 适合全文检索；文档、向量、图、时序和列式数据库分别针对灵活文档、语义相似、复杂关系、时间序列和分析扫描优化。数据库选型应由数据模型、一致性和访问模式决定。
