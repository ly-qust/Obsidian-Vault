# 项目定位与业务主链

[[00-SmartRenew项目知识地图|返回知识地图]] · [[02-Security与JWT请求链|下一篇：Security]]

## 1. 项目定位

SmartRenew 是补贴申请与发券核销平台，覆盖：活动配置、用户申请、材料提交、审核、额度扣减、发券、商户验券与核销。项目重点不是普通 CRUD，而是多角色权限、状态流转、可靠消息和高并发一致性。

## 2. 角色边界

| 角色 | 主要能力 |
|---|---|
| USER | 申请补贴、提交材料、查看自己的申请和券 |
| REVIEWER | 领取并处理审核任务 |
| ADMIN | 配置活动、规则、额度池并查看管理数据 |
| MERCHANT | 验券、核销、查看本商户核销记录 |

角色权限只解决“能否进入某类接口”；“只能看自己的申请”“只能看本商户核销记录”还要在 Service 层做资源归属校验。

## 3. 业务主链

```text
管理员配置活动/规则/额度池
→ 用户创建申请并上传材料
→ 提交审核：锁定申请、校验状态、写Outbox
→ MQ消费者通过Inbox去重并创建审核任务
→ 审核通过
→ Redis预占额度
→ MySQL条件扣减并创建补贴券
→ 商户验券
→ 幂等核销并写入write_off
```

## 4. 为什么采用模块化单体

- 业务边界清楚，但当前规模没有必要承担微服务部署和分布式事务成本；
- 模块内可以使用本地事务保证强一致；
- 跨模块异步链路仍通过 Outbox/Inbox 展示可靠消息能力；
- 后续若流量和团队规模增长，可沿模块边界拆分。

## 5. 90 秒项目回答

> SmartRenew 是一个补贴申请、审核、发券和商户核销平台。我采用模块化单体组织用户、活动、申请、审核、额度、券和商户模块。用户提交申请时，在本地事务中锁定申请、校验状态并写入 Outbox，事务提交后发送 RabbitMQ；消费端使用 Inbox 和业务唯一约束避免重复创建审核任务。审核通过后，Redis 负责高并发额度预占，MySQL 通过条件更新和事务做最终防超发，失败时再补偿 Redis。商户核销同时处理网络重试与并发竞争：同一商户的幂等键返回首次结果，商户订单号防重复业务单，券状态和版本条件更新决定并发胜者，`write_off.voucher_id` 唯一约束做最终兜底。
