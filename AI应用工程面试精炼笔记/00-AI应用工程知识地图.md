# AI 应用工程知识地图

> [!important] Batch 5 范围
> 第一轮只掌握“可靠调用 → 上下文与结构化输出 → RAG → 项目映射”这条主线。Agent、Tool Calling、MCP、Guardrail 先保留入口，不在本轮扩写成完整教材。

## 面试主线

```text
用户请求
→ 鉴权与参数校验
→ 可靠调用模型 API
→ 组织上下文 / 记忆
→ 必要时检索知识库
→ 约束输出并校验
→ 引用、降级、日志与追踪
```

## 主题地图

| 主题 | 本轮结论 | 深入入口 |
|---|---|---|
| LLM API 与 HTTP | 模型调用首先是一个不稳定的外部网络依赖 | [[AI应用工程面试精炼笔记/01-LLM-API与HTTP可靠调用]] |
| Context / Memory | 上下文是本次请求携带的信息，记忆是跨请求保存并按会话取回的信息 | [[AI应用工程面试精炼笔记/02-Context-Memory与Structured-Output]] |
| Structured Output | 把自然语言结果约束为可校验的数据契约，不能只相信“看起来像 JSON” | [[AI应用工程面试精炼笔记/02-Context-Memory与Structured-Output]] |
| RAG | 先检索可信资料，再让模型基于证据组织答案 | [[AI应用工程面试精炼笔记/03-RAG核心链路]] |
| SmartRenew AI | 已实现的是受控只读问答链路；项目不让模型参与审核、额度、发券和核销 | [[AI应用工程面试精炼笔记/04-SmartRenew-AI项目映射与高频问答]] |
| Agent | 多步规划和执行的更大编排形态 | P1 入口，后续再学 |
| Tool Calling | 模型提出工具名和参数，应用程序负责真正执行并回传结果 | P1 入口，后续再学 |
| MCP | 统一连接外部工具/资源的协议层 | P2 入口，后续再学 |
| Guardrail | 请求前后进行输入、输出和策略拦截 | P2 入口，后续再学 |

- 能画出 RAG 的索引链和查询链，并指出检索质量风险。
