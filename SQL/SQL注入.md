select count(*) from emp where username = ? and password = ?
### 1. SQL 结构与参数分离

SQL 语句（如 `select count(*) from emp where username = ? and password = ?`）会被**预先编译**，数据库先解析并固定 SQL 的**逻辑结构**（表、字段、查询条件的框架）。而用户输入的参数（如 `sjdkfjkdjfks`、`' or '1' = '1`）是**后续单独传入**的，两者在处理阶段完全隔离。

### 2. 参数被当作 “纯数据” 处理

数据库在执行时，会将传入的参数视为**普通字符串 / 数据**，而非 SQL 语句的一部分。例如，参数中的单引号、`or '1'='1` 等恶意内容，会被当作 “普通字符” 存储或比对，不会被解析为 SQL 逻辑。

### 3. 杜绝恶意 SQL 拼接

传统 “字符串拼接” 方式（如 `"... where username = '" + 恶意参数 + "'"`）会让攻击者通过构造参数（如 `' or '1'='1`）拼接出非法 SQL。而预编译将 SQL 结构固定，参数无法改变 SQL 的逻辑，因此彻底避免了这种风险。

总之就是将SQL模板与参数数据分割开，？引入的是整个字符串，不与原来的SQL语句相关联
