# OS、并发、IO 与 Java 21 高频自测

> 当前面试主入口：[[操作系统面试精炼笔记/00-操作系统知识地图]]

## 使用方法

1. 每题先闭卷说 30 秒：结论 → 因果链 → Java/Linux 关联 → 边界。
2. 能答主问题但追问卡住，状态记为“需回炉”；完全流畅再记“已掌握”。
3. 表中的“30 秒检查点”不是完整答案，完整解释回到对应主笔记。

> [!danger] 高频错误
> 不要只背名词。若无法画出 VA 翻译、Socket/FD/epoll、Virtual Thread/Carrier/OS Thread 三张链路图，视为没有真正掌握。

## 40 题闭卷矩阵

| # | 问题 | 30 秒答案检查点 | 追问方向 | 常见错误答案 |
|---|---|---|---|---|
| 1 | 进程和线程区别？ | 资源隔离 vs 执行调度；共享堆/FD，私有栈/寄存器 | 故障影响、IPC | 线程无资源 |
| 2 | 为什么线程切换通常更轻？ | 共享地址空间；仍有现场和缓存成本 | TLB/Cache | 切换零成本 |
| 3 | Ready 和 Blocked 区别？ | Ready 只缺 CPU；Blocked 给 CPU 也不能推进 | 状态转换 | 都是没 CPU |
| 4 | 常见 IPC 如何选？ | 管道、MQ、共享内存、信号、Socket | 数据边界、同步 | IPC 只有 Socket |
| 5 | 什么是虚拟内存？ | 独立 VAS、映射、隔离、保护、按需分配 | Swap 边界 | 虚拟内存就是磁盘 |
| 6 | VA 到 PA 完整链？ | VPN+Offset → TLB → PTE/PFN → 原 Offset | 多级页表 | VA 存在页表里 |
| 7 | 页表与 TLB 区别？ | 映射结构 vs 地址翻译缓存 | CPU Cache | TLB 存业务数据 |
| 8 | TLB Miss 一定缺页吗？ | PTE 可有效且驻留 | 三条路径 | 一定在磁盘 |
| 9 | Page Fault 一定读磁盘吗？ | 零页/已有页/非法访问/文件/Swap | 指令重试 | 缺页定义就是换入 |
| 10 | 为什么申请 100MB 不一定占 100MB RAM？ | VAS 预留 + Demand Paging | VSZ/RSS | 立即分配全部物理页 |
| 11 | JVM 堆栈与 VAS 什么关系？ | 都位于进程地址空间；堆共享、栈私有 | OOM/Direct | JVM 绕过 OS |
| 12 | Java read 与 Linux read 关系？ | API → JDK/JVM/native → 可能 syscall | ByteArray/Buffer | 一一对应 |
| 13 | 每次 Java read 都系统调用吗？ | 纯内存流与用户态缓冲可避免 | 页缓存 | 必然陷入内核 |
| 14 | native code 与 JNI 区别？ | 本机代码实体 vs 交互接口 | JVM/JDK | JNI 就是一段 C |
| 15 | 系统调用/中断/异常区别？ | 应用主动/硬件异步/当前指令同步 | Page Fault | 都叫中断 |
| 16 | FD 是什么？ | 进程内整数句柄，引用内核对象 | 泄漏/close | FD 是文件内容 |
| 17 | Socket 为什么可用 FD？ | 统一句柄抽象；内核对象仍是 Socket | read/write | Socket 是磁盘文件 |
| 18 | TCP 连接怎样标识？ | 源/目的 IP+Port 四元组 | NAT/listen | 两个端口 |
| 19 | listen 与 accept 后 Socket 区别？ | 监听 FD 继续接入；新 FD 服务连接 | 一个端口多连接 | accept 替换监听 FD |
| 20 | Race Condition 是什么？ | 结果依赖并发交错并可能错误 | count++ | 多线程即竞态 |
| 21 | Critical Section 是什么？ | 必须整体保护共享不变量的代码 | 锁粒度 | 整个方法都该锁 |
| 22 | 互斥与同步区别？ | 不能一起干 vs 什么时候能干 | 生产消费 | 完全同义 |
| 23 | synchronized 与 ReentrantLock？ | 自动释放 vs tryLock/中断/Condition/finally | 选型 | Lock 永远更快 |
| 24 | Condition 与 Lock 关系？ | Lock 互斥；Condition 等待条件 | 多等待队列 | Condition 是另一把锁 |
| 25 | await 为什么用 while？ | 唤醒不等于条件仍成立 | signal | if 永远足够 |
| 26 | Semaphore 解决什么？ | N permits 限并发 | 资源池 | 它就是连接池 |
| 27 | CAS 是什么？ | expected 相等才原子写入 | 自旋成本 | 永远成功 |
| 28 | AtomicInteger 保证整段业务原子吗？ | 单方法原子，多步仍可交错 | 条件扣减 | 换 Atomic 即全安全 |
| 29 | ABA 是什么？ | A→B→A，CAS 忽略历史 | Stamp | CAS 失败就是 ABA |
| 30 | 死锁四条件与规避？ | 四条件；固定顺序/超时/缩短持锁 | 活锁饥饿 | 多加锁可避免 |
| 31 | 阻塞与非阻塞 IO？ | 不能完成时等待 vs 立即返回 | EAGAIN | 阻塞 CPU |
| 32 | 非阻塞为何还要 epoll？ | 单次返回不能发现大量 FD 谁 ready | Busy Polling | 非阻塞自动回调 |
| 33 | IO 多路复用解决什么？ | 内核等待 FD 集合并返回 ready set | 同步 IO | 一次读取所有数据 |
| 34 | select/poll/epoll 区别？ | 集合/扫描 vs 注册+ready 集合 | 活跃比例 | epoll 永远 O(1) |
| 35 | epoll_wait 阻塞为何仍配非阻塞 Socket？ | 等任一 FD；单 FD read 防 EventLoop 卡死 | 读到 EAGAIN | ready 必然完整消息 |
| 36 | epoll 后还需要线程吗？ | ready 发现后仍要协议、业务、DB、CPU | Worker | epoll 自动执行业务 |
| 37 | 阻塞/非阻塞与同步/异步？ | 调用等待维度 vs 完成责任/通知维度 | Unix multiplexing | 同步=阻塞 |
| 38 | Java 21 虚拟线程解决什么？ | 降低大量等待任务的平台线程成本 | CPU-bound | 所有任务加速 |
| 39 | Virtual Thread 与 epoll 区别？ | JVM 任务调度层 vs OS FD 就绪层 | 内核 IO | 虚拟线程就是 epoll |
| 40 | 为什么虚拟线程仍需连接池与限流？ | 下游容量不随线程数增长 | Hikari20/pinning | 线程越多吞吐越高 |
