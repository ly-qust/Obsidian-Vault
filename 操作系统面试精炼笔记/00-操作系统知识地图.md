## 深度边界

- 【必须会】：可解释、可画链、能承受 1～2 层追问。
- 【高频进阶】：TLB/Page Fault、CAS/ABA、Condition、epoll、Virtual Thread/pinning。
- 【了解即可】：HotSpot/epoll/futex 源码、x86 页表位拆分、CR3/TLB shootdown、io_uring、内核调度器实现与 MMU 电路。

> [!danger] 地图级高频错误
> - OS 状态与 Java Thread.State 不能逐项机械映射。
> - 虚拟内存不等于 Swap，TLB Miss 不等于 Page Fault。
> - Java read 不等于每次 Linux read，JNI 不等于 native code。
> - Non-blocking 不等于 multiplexing，同步不等于阻塞。
> - Virtual Thread 不等于 epoll，也不会扩大数据库连接池。

## 60 秒总回答

> 进程提供地址空间、FD 和故障隔离，线程在进程内共享堆与资源并承担执行，所以更轻也会产生竞态。CPU 用 TLB 和页表把虚拟地址翻译成物理地址，合法缺页由内核按需补齐。Java 访问文件和网络时可能经 JDK/JVM、native 与系统调用进入内核，并通过 FD 引用文件或 Socket。大量连接可用 non-blocking Socket 与 epoll 等多路复用发现就绪事件，业务仍需线程处理。Java 21 虚拟线程在 JVM 层降低大量 IO 等待任务绑定平台线程的成本，但 CPU、连接池、DB、Redis 和 LLM QPS 仍是容量边界。
