# 进程基本状态与 IPC

> 当前面试主入口：[[操作系统面试精炼笔记/00-操作系统知识地图]]
> 本文聚焦进程生命周期和进程间通信，不展开网络协议细节。

## 一句话结论

进程状态描述“现在能不能运行以及在等什么”，IPC 解决“不同进程如何交换数据或同步事件”，隔离越强通常通信成本越高。

## 1. 基本状态与转换

```text
New
→ Ready（创建完成，等待调度）
→ Running（获得 CPU）
→ Waiting/Blocked（等待 I/O、事件或资源）
→ Ready（等待条件满足）
→ Terminated（退出）
```

- **New**：控制信息和地址空间正在建立。
- **Ready**：具备运行条件，但暂时没有获得 CPU。
- **Running**：正在某个 CPU 上执行。
- **Blocked/Waiting**：不能靠继续占用 CPU 立即推进，例如等待 I/O、锁、子进程或事件。
- **Terminated**：执行结束，内核仍可能短暂保留退出信息供父进程读取。

状态变化的因果链是：事件发生 → 调度器或内核记录状态 → 放入相应队列 → 条件满足后重新竞争 CPU。不同教材可能把 Waiting、Blocked、Ready 划分得略有不同，回答时先说明口径。

## 2. IPC 方式对比

| 方式 | 核心特点 | 适合回答的边界 |
|---|---|---|
| 匿名管道 | 亲缘进程之间的字节流，方向和生命周期较受限 | 父子进程简单传输 |
| 命名管道 | 通过文件系统名字找到通信端点，可跨无亲缘进程 | 本机简单流式通信 |
| 消息队列 | 以消息为单位，由内核或运行时管理排队 | 结构化消息和异步解耦 |
| 共享内存 | 多进程映射同一片物理内存，数据交换快 | 大数据量；必须另配同步机制 |
| 信号 | 轻量事件通知，承载数据能力有限 | 中断、终止、重载等控制事件 |
| Socket | 进程间端点，可本机或跨主机 | 服务进程、跨机器通信 |

共享内存不是“天然线程安全”：多个进程同时读写仍需要互斥、信号量或其他协议。管道和消息队列也不是无限容量，写端可能因缓冲区满而等待。

## 3. Java / Linux 关联

- Java 进程之间可以通过 `ProcessBuilder` 启动子进程，并读写其标准输入输出；这属于进程间通信，不等同于线程间共享堆。
- Java 多线程在同一进程内共享堆，通信成本和隔离边界与进程 IPC 不同；Java 的 `wait/notify`、锁和并发容器不要在本篇重复展开。
- Linux 的 `ps`、`pgrep`、`kill`、`systemctl`、`journalctl` 用于观察和控制进程/服务；`kill -9` 是强制终止，不能当作常规优雅停止。
- 僵尸进程通常是子进程已退出但父进程尚未回收退出状态；孤儿进程则是父进程先退出后由系统接管，二者不要混淆。

## 容易答错点

- “Blocked 就是没有 CPU”：更准确是当前状态不能继续运行，原因可能是 I/O、锁或事件等待。
- “IPC 都要复制数据”：共享内存可以减少数据复制，但同步和一致性责任转移给应用。
- “信号可以传大段业务数据”：信号主要传递事件和少量信息，不适合大数据传输。
- “进程结束后立刻完全消失”：父进程可能还需要读取退出码，因此会短暂保留退出信息。

## 高频追问

1. 共享内存为什么快、为什么还需要信号量？——数据直接落在共享区域，减少复制；并发读写顺序仍需同步。
2. 管道和消息队列怎么区分？——管道偏字节流，消息队列保留消息边界并通常支持按类型取消息。
3. Java 服务为什么常用 MQ 而不是直接共享内存？——跨进程/跨机器、持久化、重试和解耦能力更强；代价是序列化、延迟和运维复杂度。
