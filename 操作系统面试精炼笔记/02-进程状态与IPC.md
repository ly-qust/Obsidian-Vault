# 进程状态与 IPC

> 当前面试主入口：[[操作系统面试精炼笔记/00-操作系统知识地图]]

## 核心一句话

【必须会】Ready 表示万事俱备只缺 CPU，Blocked 表示即使立刻给 CPU 也无法继续；IPC 则让默认隔离的进程交换数据或同步事件。

## 状态为什么会转换

~~~text
New：创建控制信息和地址空间
↓
Ready：已经具备运行条件，等待 CPU
↓ 被调度
Running：正在 CPU 上执行
├─ 时间片到/被抢占 → Ready
├─ 等待 IO、锁、事件 → Blocked
└─ 执行结束 → Terminated

Blocked
↓ IO完成 / 锁可用 / 事件发生
Ready
↓ 重新竞争CPU，而不是直接保证Running
~~~

| 状态 | 给它 CPU 能否立刻推进 | 关键原因 |
|---|---|---|
| Ready | 能 | 只是暂时没有 CPU |
| Running | 正在推进 | 已获得 CPU |
| Blocked/Waiting | 不能 | 还在等待 IO、锁、事件或资源 |

Java Thread.State 是 JVM/API 视角，不能把 RUNNABLE、BLOCKED、WAITING 与教材 OS 状态机械一一对应。

## 为什么需要 IPC

~~~text
进程有独立地址空间
↓
普通指针不能直接访问另一个进程的数据
↓
需要内核或约定的共享映射建立通信通道
↓
根据数据量、边界、可靠性和部署范围选择IPC
~~~

| 方式 | 数据/事件形态 | 适用场景与代价 |
|---|---|---|
| 匿名管道 | 字节流 | 亲缘进程简单传输；方向、容量和生命周期受限 |
| 命名管道 | 有名字的字节流端点 | 本机无亲缘进程也可发现 |
| 消息队列 | 保留消息边界 | 异步解耦；有排队、复制和容量管理 |
| 共享内存 | 多进程映射同一物理页 | 数据交换快；必须另配同步协议 |
| 信号 | 轻量事件 | 控制通知，不适合承载大段业务数据 |
| Socket | 本机或跨主机端点 | 服务间通信；涉及协议、缓冲和网络失败 |

## 共享内存为什么还要锁

~~~text
进程A和进程B映射同一物理区域
↓
省去通过消息通道反复复制大块数据
↓
但多个执行流仍可能同时读改写
↓
出现竞态与中间状态
↓
必须用互斥量、信号量或无锁协议协调
~~~

同步原语主解释见 [[操作系统面试精炼笔记/05-同步互斥信号量与死锁]]。

## Java / Linux / SmartRenew 关联

- ProcessBuilder 可启动子进程并读写标准输入输出；这属于 IPC，不等于线程间共享 Java 堆。
- Java 多线程共享同一 JVM 堆，通信更直接，但隔离更弱。
- Linux 的 ps、pgrep、kill、systemctl、journalctl 用于观察和控制进程；kill -9 不能作为常规优雅停机方案。
- 僵尸进程是子进程已退出但父进程尚未回收退出状态；孤儿进程是父进程先退出后由系统接管。
- SmartRenew 使用 RabbitMQ 是跨进程/服务的消息通信与异步解耦；不要把 MQ 说成本机内核消息队列或共享内存。

> [!danger] 高频错误
> - “Ready 和 Blocked 都只是没拿到 CPU”错误：Blocked 即使给 CPU 也无法推进。
> - “条件满足后 Blocked 直接变 Running”错误：通常先进入 Ready 再竞争 CPU。
> - “共享内存天然线程安全”错误：只减少复制，不保证并发顺序。
> - “信号适合传输大业务对象”错误：信号主要用于事件通知。

## 高频面试题

### 1. Ready 和 Blocked 有什么区别？

- **30 秒答案**：Ready 已具备运行条件，只缺 CPU；Blocked 还在等 IO、锁或事件，即使立即分配 CPU 也无法继续。等待条件满足后通常回到 Ready，再竞争 CPU。
- **追问方向**：Running 如何进入两种状态？Java RUNNABLE 是否等于 OS Running？
- **常见错误答案**：两者都是“CPU 不够”。

### 2. 常见 IPC 有哪些，如何选择？

- **30 秒答案**：管道适合简单字节流，消息队列保留消息边界，共享内存适合大数据但要额外同步，信号适合事件，Socket 可跨主机。选择看部署范围、数据量、消息边界、可靠性和同步成本。
- **追问方向**：共享内存为什么快？Socket 和管道有何不同？
- **常见错误答案**：IPC 只有 Socket，或共享内存不经过任何内核管理。

### 3. 共享内存为什么快，为什么仍需信号量？

- **30 秒答案**：多个进程把同一物理页映射进各自地址空间，交换大数据时可减少通道复制；但并发读改写仍会交错，所以要用互斥、信号量或协议保证一致性。
- **追问方向**：共享页是否破坏进程隔离？计数信号量表达什么？
- **常见错误答案**：映射同一内存后所有操作自动原子。

### 4. 僵尸进程和孤儿进程有什么区别？

- **30 秒答案**：僵尸是子进程已退出，但父进程还没读取退出状态；孤儿是父进程先退出，仍运行的子进程由系统接管。二者原因和资源状态不同。
- **追问方向**：为什么退出信息要暂存？如何排查大量僵尸？
- **常见错误答案**：僵尸进程仍在正常执行并占满 CPU。

## D1 闭卷题

不看答案画出 New、Ready、Running、Blocked、Terminated 的转换，并用一句话证明 Ready 与 Blocked 不是同一种等待。
