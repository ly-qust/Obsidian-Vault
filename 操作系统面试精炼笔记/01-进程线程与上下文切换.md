# 进程、线程与上下文切换

> 当前面试主入口：[[操作系统面试精炼笔记/00-操作系统知识地图]]

## 核心一句话

【必须会】进程是资源与隔离边界，线程是进程内的执行与调度单位；同进程线程共享更多资源，所以切换通常比进程轻，但共享也带来竞态风险。

## 为什么要分进程和线程

~~~text
程序需要隔离地址空间、文件和权限
↓
操作系统用进程承载资源边界
↓
一个进程又希望并发推进多个任务
↓
在线程之间共享代码、堆和打开资源
↓
线程只保留自己的执行现场
↓
获得更低的创建/切换成本，但必须处理共享数据安全
~~~

| 维度 | 进程 Process | 线程 Thread |
|---|---|---|
| 核心角色 | 资源分配与故障隔离边界 | 执行流和常见调度单位 |
| 地址空间 | 通常各自拥有虚拟地址空间 | 同进程线程共享地址空间 |
| 通常共享 | 不同进程默认不共享，要通过 IPC | 代码、堆、静态数据、打开的 FD |
| 私有执行现场 | 进程管理信息等 | 栈、寄存器、程序计数器、线程状态 |
| 故障影响 | 通常限制在本进程 | 错误可能破坏同进程共享状态 |

> “线程是 CPU 调度最小单位”是常用面试口径；更严谨地说，现代通用 OS 通常调度内核可见线程，具体内核对象名称不要绝对化。

## 上下文切换完整因果链

~~~text
当前线程运行
↓ 时间片耗尽 / 被抢占 / 主动阻塞 / 被唤醒后竞争
CPU进入调度路径
↓
保存寄存器、程序计数器、栈指针等执行现场
↓
调度器选择另一个 Ready 线程
↓
恢复目标线程执行现场
↓
目标线程继续运行
~~~

线程切换通常不必切换整套进程资源视图，因此往往比进程切换轻；但它仍有调度、寄存器保存恢复、缓存局部性下降和共享数据同步成本。“轻”不等于“免费”，也不要背固定微秒数字。

## 进程切换为什么通常更重

~~~text
切换到另一个进程
↓
执行现场改变
↓
地址空间和相关内存映射上下文也可能改变
↓
缓存/TLB局部性可能受到更大影响
↓
隔离更强，但平均成本通常更高
~~~

同一进程内线程共享页表所描述的地址空间，这是线程切换通常更轻的重要原因之一。地址转换主解释见 [[操作系统面试精炼笔记/04-虚拟内存页表TLB与缺页]]。

## Java 与 Linux 如何对应

- Java 平台线程通常封装 OS 线程，OS 最终把平台线程调度到 CPU。
- Java 21 虚拟线程仍是 java.lang.Thread，由 JVM 调度到载体/平台线程；载体线程再由 OS 调度。完整主解释见 [[操作系统面试精炼笔记/07-Java21虚拟线程与IO]]。
- Thread.start() 创建并调度新的执行单元；直接调用 run() 只是当前线程中的普通方法调用。
- Java Thread.State 与教材的 Ready/Running/Blocked 不是逐项同名映射；OS 状态主解释见 [[操作系统面试精炼笔记/02-进程状态与IPC]]。
- Linux 可用 ps -eLf、top -H -p PID 观察线程，用 JVM thread dump 观察 Java 栈和锁等待。

> [!danger] 高频错误
> - “线程没有自己的资源”错误：它有私有栈、寄存器上下文和程序计数器。
> - “线程切换没有成本”错误：仍有调度、现场保存恢复和缓存局部性损失。
> - “Java 线程由 JVM 独立于 OS 调度”错误：平台线程最终仍由 OS 调度。
> - “虚拟线程就是请求状态对象/普通协程”错误：它是真实的 Java Thread 抽象，语义不能与所有协程实现等同。

## 高频面试题

### 1. 进程和线程有什么区别？

- **30 秒答案**：进程偏资源分配和隔离，通常拥有独立虚拟地址空间；线程偏执行和调度，同进程线程共享代码、堆和 FD，但各有栈、寄存器和程序计数器。共享让线程更轻，也让并发安全成为问题。
- **追问方向**：进程间如何通信？线程崩溃为什么可能影响整个进程？
- **常见错误答案**：线程完全没有资源；进程只是“大线程”。

### 2. 为什么线程切换通常比进程切换轻？

- **30 秒答案**：同进程线程共享地址空间和大部分资源映射，切换时主要保存恢复执行现场；进程切换还可能改变地址空间上下文，对 TLB 和缓存局部性的影响通常更大。但线程切换仍然不是零成本。
- **追问方向**：上下文包含什么？线程越多为什么吞吐可能下降？
- **常见错误答案**：线程切换只改一个线程 ID，所以没有成本。

### 3. 线程什么时候发生上下文切换？

- **30 秒答案**：时间片耗尽、优先级抢占、线程主动让出、等待锁或 IO 进入阻塞，以及阻塞完成后重新参与调度，都可能引出调度切换。
- **追问方向**：阻塞线程是否占 CPU？Ready 与 Blocked 有何区别？
- **常见错误答案**：只有调用 sleep 才会切换。

### 4. 多线程为什么能利用多核？

- **30 秒答案**：多个内核可见的可运行线程可以被 OS 同时调度到不同 CPU 核；是否真正并行还受核心数、同步、CPU 配额和任务类型限制。
- **追问方向**：并发与并行区别？单核上多线程有没有意义？
- **常见错误答案**：创建多少线程就有多少任务同时并行。

### 5. Java 平台线程、虚拟线程和 OS 线程如何对应？

- **30 秒答案**：平台线程通常与 OS 线程近似 1:1；大量虚拟线程由 JVM 调度到较少的载体平台线程，OS 只调度这些平台线程到 CPU。虚拟线程没有取消 OS 线程。
- **追问方向**：虚拟线程阻塞时怎样卸载？什么是 pinning？
- **常见错误答案**：虚拟线程直接由 CPU 调度，或者完全不经过内核。

## D1 闭卷题

画出“进程资源边界 → 线程共享/私有资源 → 上下文切换 → Java 平台/虚拟线程 → OS 调度 → CPU”的完整链路。
