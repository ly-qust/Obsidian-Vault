## 五条线怎样汇合

~~~text
进程提供VAS和FD表
↓
线程在进程内执行Java任务
↓
共享堆导致竞态，需要并发原语
↓
线程通过Java IO与系统调用访问Socket
↓
内核用FD与epoll等机制管理就绪
↓
Java 21虚拟线程降低大量等待任务绑定平台线程的成本
↓
CPU、连接池、DB、Redis、LLM QPS仍是最终容量边界
~~~

## 学习深度边界

- 【必须会】：进程/线程、状态、VAS、TLB、Page Fault、竞态、锁、系统调用、FD、阻塞/非阻塞、虚拟线程边界。
- 【高频进阶】：CAS/ABA、Condition、epoll、同步/异步、pinning。
- 【了解即可】：HotSpot 调度器源码、epoll 内核源码、x86 页表位拆分、TLB shootdown、io_uring、CFS/EEVDF、futex 与 MMU 电路。

> [!danger] 高频错误
> 五条主线不能互相替代：虚拟内存不是 Swap，TLB 不是数据缓存，Condition 不是 Lock，epoll 不是虚拟线程，虚拟线程也不是下游容量扩容器。

## 高频面试题

### 1. 五条主线中哪条负责隔离？

- **30 秒答案**：进程 VAS 与页表权限负责地址隔离；线程共享同一进程地址空间。
- **追问方向**：共享内存如何突破默认隔离？
- **常见错误答案**：Java 堆本身提供跨进程隔离。

### 2. 哪条线负责并发正确性？

- **30 秒答案**：共享数据 → 竞态 → 临界区 → 互斥/同步原语；epoll 和虚拟线程只改变 IO 发现或任务承载，不自动保证业务原子性。
- **追问方向**：Atomic 多步业务为什么仍出错？
- **常见错误答案**：用了虚拟线程就不需要锁。

### 3. 哪条线解释 Java read？

- **30 秒答案**：Java API → JDK/JVM/native → 可能的系统调用 → 内核对象；是否每次进入内核取决于流类型和缓冲。
- **追问方向**：ByteArrayInputStream 与 BufferedInputStream。
- **常见错误答案**：Java read 与 Linux read 一一对应。

### 4. 哪条线解释高连接数？

- **30 秒答案**：Socket/FD → non-blocking → multiplexing → epoll 负责 ready 发现；Worker、数据库与连接池负责后续业务。
- **追问方向**：为什么 epoll 后仍需线程？
- **常见错误答案**：epoll 自动完成请求。

### 5. 哪条线解释高等待任务数？

- **30 秒答案**：Virtual Thread → JVM Scheduler → Carrier → OS Thread，降低等待任务占用平台线程的成本；底层 IO 与下游容量不变。
- **追问方向**：pinning、Hikari 20 连接。
- **常见错误答案**：10000 虚拟线程等于 10000 CPU 并行。
