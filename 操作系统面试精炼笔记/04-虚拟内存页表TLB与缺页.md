# 虚拟内存、页表、TLB 与缺页

> 当前面试主入口：[[操作系统面试精炼笔记/00-操作系统知识地图]]

## 核心一句话

【必须会】虚拟内存首先是“每个进程独立虚拟地址空间”的抽象与保护机制，不是磁盘；页表保存地址映射，TLB 缓存映射，Page Fault 让内核补齐或拒绝当前访问。

## 五个概念先分开

| 概念 | 含义 | 不是 |
|---|---|---|
| Virtual Address, VA | CPU 当前指令要访问的虚拟地址 | 页表里预存的一张地址清单 |
| Virtual Address Space, VAS | 一个进程可见的虚拟地址范围与布局 | 全部都已占用物理内存 |
| Page Table | 当前进程虚拟页到物理页的映射结构 | 业务数据缓存 |
| PTE | 一个页表项，含 PFN、存在位、权限等 | 完整物理页内容 |
| TLB | CPU 侧热点地址翻译缓存 | 保存 Java 对象/SQL 结果的 CPU Cache |

虚拟地址可以来自指针、寄存器、对象引用计算或指令取址结果。CPU 用它发起访问，页表用于翻译它；不能说“虚拟地址保存在页表里”。

## 为什么需要虚拟地址空间

~~~text
多个进程都想使用连续、稳定的地址
↓
物理内存实际分散且容量有限
↓
OS为每个进程提供独立VAS
↓
页表把虚拟页按需映射到物理页
↓
同一虚拟地址在不同进程可映射到不同PFN
↓
实现隔离、保护、共享页与按需分配
~~~

~~~text
进程A：VA 0x1000 → PFN 42
进程B：VA 0x1000 → PFN 91
~~~

两者看到相同 VA，不代表访问同一物理内存。内核也可以有意把两个进程的虚拟页映射到同一物理页，用于共享库或共享内存。PTE 中的 R/W/X、User/Supervisor 等权限帮助阻止非法访问。

## VA 到物理地址的完整链

~~~text
Virtual Address
↓ 拆分
VPN（Virtual Page Number） + Offset（页内偏移）
↓
查TLB
├─ Hit：直接得到PFN
└─ Miss：硬件/OS按体系结构遍历Page Table
        ├─ PTE有效且页面驻留：得到PFN，并回填TLB
        └─ PTE表明当前不可直接访问：触发Page Fault

Physical Address = PFN + 原来的Offset
↓
访问RAM中的对应字节
~~~

为什么 Offset 不变：分页按等大小页面/页框映射，只替换“这是哪一页”，页内第几个字节不需要改变。

【高频进阶】多级页表按层索引虚拟页号，避免为稀疏 VAS 一次性分配巨大连续页表。面试说清“按需分配页表层级”即可，不背 x86 位拆分。

## TLB 与 CPU Cache 不同

~~~text
TLB：VPN → PFN 等地址翻译
CPU Cache：物理/缓存地址对应的数据或指令副本
~~~

一次访问可能 TLB 命中但数据 Cache 未命中，也可能 TLB 未命中后从页表找到有效 PTE。两者优化的对象完全不同。

## 三种结果不能混淆

| 场景 | TLB | Page Table/PTE | 是否 Page Fault | 结果 |
|---|---|---|---|---|
| TLB Hit | 有翻译 | 无需本次遍历 | 否 | 得到 PFN 后访问内存层次 |
| TLB Miss + Page Hit | 没缓存翻译 | PTE 有效且驻留 | 否 | 页表遍历，回填 TLB |
| Page Fault | 通常无法由 TLB 得到可用翻译 | 不驻留、尚未分配、权限或映射问题 | 是 | CPU 进入内核异常处理 |

因此 TLB Miss 不等于 Page Fault；前者可能只是地址翻译缓存没命中。

## Page Fault 完整处理链

~~~text
CPU执行访存指令
↓
发现PTE当前不能完成访问
↓
触发Page Fault异常，进入Kernel
↓
内核检查VA是否属于合法映射、访问权限是否允许
├─ 非法地址/权限 → 向进程报告错误，可能终止
└─ 合法按需访问
    ↓
    分配或找到Physical Frame
    ↓
    必要时从文件/交换区加载，或提供零页
    ↓
    更新PTE、权限和相关状态
    ↓
    返回用户态，重新执行原访存指令
~~~

Page Fault 不一定读磁盘：

- 新匿名页可能只需分配并清零。
- 可执行文件、共享库、mmap 文件可能从对应文件加载。
- 被换出的匿名页才可能从 Swap 换入。
- 非法地址/权限错误不会通过“读磁盘”修好。
- 某些页面已经在内存但映射/权限状态需要内核处理。

## Demand Paging 与“申请 100MB”

~~~text
程序/JVM预留或扩展100MB虚拟地址范围
↓
先建立VAS范围或懒分配约定
↓
尚未触碰的页不一定立即获得独立物理页
↓
首次写入某页触发合法Page Fault
↓
按需分配Physical Frame
~~~

所以申请 100MB 不等于瞬间占用 100MB RAM。反过来，“不在 RAM”也不等于“一定在 Swap”，它可能来自可执行文件、动态库、mmap 文件、尚未实际分配的匿名页或共享零页。

## JVM 堆、线程栈与 VAS

~~~text
JVM进程Virtual Address Space
├─ Java Heap（线程共享的JVM逻辑区域）
├─ 每个平台线程/相关执行栈
├─ Metaspace与JIT代码等native区域
├─ Direct Buffer / mmap
└─ JDK、共享库和其他映射
~~~

- 堆和栈都是进程 VAS 中的区域，不是脱离 OS 的特殊物理内存。
- 同进程线程共享地址空间与堆，但各自有执行栈、寄存器和程序计数器。
- GC 管理 Java 对象可达性和堆空间；页表、TLB、缺页和物理页由硬件/OS 管理。
- OutOfMemoryError 可能来自堆、元空间、直接内存、线程创建或容器限制，不等于机器物理 RAM 必然耗尽。

Linux 观察入口：free -h、vmstat、/proc/meminfo、进程 RSS/VSZ、容器 cgroup 限制；Java 排查回看 [[java八股文/Java后端完整知识体系/07-JVM内存类加载GC与调优]]。

> [!danger] 高频错误
> - “虚拟内存就是磁盘/Swap”错误：它首先是地址空间、映射和保护抽象。
> - “虚拟地址保存在页表”错误：页表保存虚拟页到物理页的映射项。
> - “TLB 保存业务数据”错误：TLB 缓存地址翻译。
> - “TLB Miss 就是 Page Fault”错误：PTE 可能有效且页面在 RAM。
> - “Page Fault 一定访问磁盘”错误：零页、权限错误、已有页映射等路径不需要磁盘 IO。
> - “不在 RAM 就一定在 Swap”错误：还可能来自文件映射、未分配匿名页等。
> - “JVM 堆就是物理内存”错误：堆是 VAS 中的 JVM 逻辑区域。

## 高频面试题

### 1. 什么是虚拟内存？

- **30 秒答案**：虚拟内存是 OS 和硬件给进程提供的独立虚拟地址空间抽象，通过页表把虚拟页映射到物理页，实现隔离、保护、共享和按需分配；Swap 只是可能使用的后备机制。
- **追问方向**：同一 VA 为什么可指向不同数据？共享内存如何实现？
- **常见错误答案**：物理内存不够时拿磁盘假装内存。

### 2. 虚拟地址怎样翻译成物理地址？

- **30 秒答案**：VA 拆成 VPN 和 Offset，先查 TLB；命中得到 PFN，未命中再查页表。PTE 有效就回填 TLB，用 PFN 加原 Offset 形成物理地址；不能完成则触发缺页异常。
- **追问方向**：为什么 Offset 不变？多级页表解决什么？
- **常见错误答案**：页表直接存着所有完整虚拟地址。

### 3. 页表和 TLB 有什么区别？

- **30 秒答案**：页表是每个地址空间的映射结构，包含 PFN、存在位和权限；TLB 是 CPU 侧的热点页表项缓存，用来减少页表遍历。TLB 不保存业务数据。
- **追问方向**：TLB 与 CPU Cache 区别？进程切换为什么影响 TLB 局部性？
- **常见错误答案**：TLB 是一级数据缓存。

### 4. TLB Miss 一定是 Page Fault 吗？

- **30 秒答案**：不一定。TLB Miss 只说明翻译缓存没命中；若页表 PTE 有效且物理页驻留，遍历页表后即可继续。只有当前映射不能完成访问时才进入 Page Fault 处理。
- **追问方向**：列出 TLB Hit、TLB Miss+Page Hit、Page Fault 三条路径。
- **常见错误答案**：没命中 TLB 就说明页面在磁盘。

### 5. Page Fault 一定访问磁盘吗？

- **30 秒答案**：不一定。合法缺页可能分配零页、建立已有页映射，或从文件/Swap 加载；非法地址或权限错误则直接报告错误。是否磁盘 IO 取决于页面来源和状态。
- **追问方向**：缺页后为什么能重试原指令？什么是 major/minor fault 的概念边界？
- **常见错误答案**：Page Fault 的定义就是从 Swap 读页。

### 6. 为什么申请 100MB 不一定马上占 100MB RAM？

- **30 秒答案**：OS/JVM 可以先保留虚拟地址范围，依赖按需分页；只有实际触碰页面时才通过缺页分配物理页或建立映射。最终行为还受提交策略和运行时实现影响。
- **追问方向**：VSZ 与 RSS 有何区别？匿名页第一次写发生什么？
- **常见错误答案**：new/malloc 成功后所有字节都已经有独立物理页。

### 7. JVM 堆和操作系统虚拟内存是什么关系？

- **30 秒答案**：JVM 堆是 Java 进程 VAS 中的一块逻辑区域；GC 管对象与堆，OS/硬件管页表、TLB、缺页和物理页。线程栈、直接内存和共享库也在同一进程地址空间内。
- **追问方向**：OOM 是否等于物理内存不足？Direct Buffer 属于哪里？
- **常见错误答案**：Java 堆绕过操作系统直接管理 RAM。

## D1 闭卷题

默画 VA = VPN + Offset → TLB → Page Table/PTE → PFN + Offset → RAM；再分别写出 TLB Miss 和 Page Fault 的分叉。
