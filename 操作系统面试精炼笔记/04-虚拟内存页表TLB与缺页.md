# 虚拟内存、页表、TLB 与缺页

> 当前面试主入口：[[操作系统面试精炼笔记/00-操作系统知识地图]]
> 本文讲地址转换和缺页因果链，不展开页面置换算法计算。

## 一句话结论

虚拟内存给每个进程提供独立地址空间，页表完成虚拟地址到物理地址的映射，TLB 缓存常用映射，缺页表示当前映射或数据不在可直接访问的位置，需要内核处理。

## 1. 为什么需要虚拟内存？

- **隔离**：不同进程看到各自的地址空间，一个进程不能直接用普通指针访问另一个进程的地址。
- **抽象**：程序使用连续的虚拟地址，物理内存可以分散分配，不要求程序感知真实物理布局。
- **扩展与保护**：内核可以按页设置读写执行权限，并在物理内存紧张时结合文件映射或交换机制管理数据。

虚拟内存不是“凭空增加内存”，也不是简单等于 Swap；它首先是地址空间与保护机制，交换只是部分系统的资源管理手段。

## 2. 页表与 TLB

一次地址访问的简化链路：

```text
CPU 产生虚拟地址
→ 拆成虚拟页号 + 页内偏移
→ 先查 TLB
→ 命中：得到物理页号并拼接偏移
→ 未命中：查多级页表
→ 找到映射后更新 TLB，再访问物理内存
```

- **页表**：记录虚拟页到物理页的映射以及存在、可读写、可执行等权限。
- **多级页表**：按需分层，减少为稀疏地址空间一次性分配巨大页表的浪费。
- **TLB**：页表项的高速缓存；TLB 未命中不等于缺页，仍可能通过页表找到有效映射。

## 3. 缺页因果链

```text
访问某虚拟页
→ 页表项不存在、无权限或数据尚未准备好
→ CPU 触发缺页异常并进入内核
→ 内核判断是合法懒加载、文件映射、换入还是非法访问
→ 合法情况准备物理页/读入数据/更新页表
→ 返回用户态重试指令；非法情况向进程报告错误
```

缺页异常不是“程序一定出错”：按需分配、内存映射和加载页面都可能触发合法缺页。真正需要关注的是缺页频率、磁盘等待和工作集是否超过内存容量。

## 4. Java / Linux 关联

- JVM 堆、线程栈和元空间使用的是进程虚拟地址空间；Java 对象通常不直接等于某个固定物理页。
- GC 管理 Java 对象生命周期，页表和缺页由操作系统/硬件管理；不要说“GC 就是整理物理内存”。
- Linux 可用 `free -h`、`/proc/meminfo`、`vmstat` 观察内存和换入换出趋势；`top` 看进程层面的内存使用，仍需结合容器限制和 JVM 参数。
- Java 出现 `OutOfMemoryError` 不一定是物理内存耗尽，也可能是 Java 堆、元空间、直接内存或其他进程资源达到上限，排查入口见 [[java八股文/Java后端面试精炼笔记/03-JVM内存-GC与排查]]。

## 容易答错点

- “TLB 未命中就是缺页”：TLB 未命中可以通过页表查到映射；页表无有效映射才可能触发缺页处理。
- “缺页就是异常错误”：缺页是硬件通知内核处理的一种机制，合法按需加载也会缺页。
- “虚拟内存等于 Swap”：Swap 只是某种后备存储机制，虚拟地址空间和内存保护更基础。
- “JVM 堆就是物理内存”：堆是 JVM 在进程虚拟地址空间中的逻辑区域。

## 高频追问

1. 为什么要用 TLB？——页表可能是多级结构，TLB 缓存热点映射，减少每次访问都遍历页表的成本。
2. 缺页处理完成后为什么能继续执行？——内核补齐合法映射并更新页表，CPU 重试触发缺页的指令。
3. 内存很大为什么仍可能 OOM？——JVM 区域、容器 cgroup、地址空间、直接内存或单次分配上限都可能先达到边界。
