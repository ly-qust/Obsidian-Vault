# 用户态、内核态、系统调用与 FD

> 当前面试主入口：[[操作系统面试精炼笔记/00-操作系统知识地图]]

## 核心一句话

【必须会】Java API 是应用层入口，真正访问文件、网络和设备时可能经 JDK/JVM、native 层和系统调用进入内核；FD 只是进程引用内核对象的整数句柄。

## 为什么要分用户态和内核态

~~~text
普通应用不应任意改页表、设备或其他进程内存
↓
CPU提供不同权限级别
↓
业务代码在用户态运行
↓
需要特权能力时走受控入口
↓
系统调用进入内核态
↓
内核校验参数、权限并操作对象
↓
返回结果/错误，继续用户态代码
~~~

用户态和内核态不是两颗 CPU，也不是两个进程，而是执行代码时的权限与运行环境不同。

## Java InputStream.read 到 Linux read

~~~text
Java业务代码
↓
InputStream / Socket / Files 等Java API
↓
具体JDK实现与缓冲逻辑
↓
JVM运行时 / native桥接
↓
可能调用OS read/recv等系统调用
↓
内核校验FD、权限与缓冲状态
↓
文件系统 / 设备驱动 / 网络协议栈
↓
数据返回Java缓冲区
~~~

这是一条“可能链”，不能写成每次 Java read 都必然对应一次 Linux read：

- ByteArrayInputStream 从 Java 内存数组读取，不需要文件/网络系统调用。
- BufferedInputStream 可能一次底层读取一批字节，后续多次 Java read 直接从用户态缓冲取数据。
- 文件数据命中页缓存时仍可能经过系统调用，但不需要等待磁盘完成物理读取。
- 不同 JDK、OS、Channel 和 Socket 实现可能采用不同 native 路径。

## JDK、JVM、native 与 JNI

| 概念 | 一句话职责 | 不要混淆 |
|---|---|---|
| Java API | 给业务代码的类型和方法抽象 | API 调用不必然等于系统调用 |
| JDK 实现 | Java 类库的具体实现和缓冲策略 | 不等于 JVM 本身 |
| JVM | 执行字节码、管理运行时、协调本地能力 | 不是所有 JDK 类库代码都在 JVM 内核里 |
| native code | 用 C/C++/汇编等编译为本机指令的代码 | 它是代码实体 |
| JNI | Java 与 native code 交互的一套接口规范 | JNI 本身不是“那段 native 代码” |

## 系统调用、中断与异常

| 机制 | 触发源 | 同步性 | 例子 |
|---|---|---|---|
| System Call | 应用主动执行受控入口 | 相对当前执行流同步触发 | read、write、open、socket |
| Interrupt | 硬件/设备异步通知 CPU | 异步于当前指令流 | 网卡收包、定时器 |
| Exception | 当前指令执行产生条件 | 同步于当前指令 | 除零、非法指令、Page Fault |

三者都可能让 CPU 执行内核代码，但触发来源和语义不同。Page Fault 是 CPU 执行当前访存指令时触发的异常，不是网卡中断，也不是应用主动系统调用。

## 一次阻塞 Socket read 的真实时间线

~~~text
应用调用read(socketFd)
↓
内核检查Socket接收缓冲区
├─ 非阻塞且暂无数据 → 返回EAGAIN
└─ 阻塞且暂无数据 → 线程进入等待，调度其他线程

网卡收到数据
↓
驱动处理，中断/轮询机制通知内核
↓
内核网络协议栈处理TCP/IP
↓
数据进入Socket接收缓冲区
↓
Socket变为readable
↓
唤醒阻塞线程，或把ready事件交给epoll
↓
应用再次获得CPU并读取数据
~~~

IO 多路复用的 ready 链路主解释见 [[操作系统面试精炼笔记/06-IO多路复用与epoll]]。

## FD 是什么

~~~text
当前进程中的整数FD
↓
进程FD表项
↓
内核打开对象/状态
↓
普通文件、管道、Socket、设备等
~~~

- 0、1、2 通常是 stdin、stdout、stderr。
- FD 是进程内句柄，不是文件内容，也不一定指向普通磁盘文件。
- 多个 FD 可以引用同一内核对象；close 释放当前引用，不等于删除磁盘文件。
- FD 泄漏会触发 Too many open files；可检查 /proc/PID/fd、lsof 和 ulimit -n。

## open/read/write/close 与文件系统

~~~text
路径名
↓
目录项解析名字
↓
定位inode等元数据
↓
open返回FD
↓
read/write通过FD访问页缓存、文件系统和设备
↓
close释放当前FD引用
~~~

- 文件系统负责名称组织、元数据、权限、空间分配、数据定位和持久化语义。
- inode 通常保存权限、所有者、大小、时间和数据块定位；文件名在目录项中，不等于 inode。
- 页缓存保存近期文件数据；write 返回不一定表示数据已经持久化到物理介质。
- df 看文件系统容量，du 统计可见目录树占用；删除但仍被进程打开的文件可造成两者差异。

## Socket、监听 FD 与连接 FD

Socket 是内核维护的网络通信对象，应用通过 FD 引用它；它遵循统一的 FD 操作抽象，但不是普通磁盘文件。

~~~text
ServerSocket绑定 IP + Port
↓
内核创建监听Socket，应用持有listen FD
↓
客户端建立TCP连接
↓
accept(listenFd)
↓
返回新的connected FD
↓
listen FD继续接收其他连接
~~~

一个已建立 TCP 连接通常由四元组区分：源 IP、源端口、目的 IP、目的端口。不能简化成“两个端口之间的一根线”。

## Java / Linux / SmartRenew 关联

- Java Socket/getInputStream/getOutputStream 是 Java API，底层可关联内核 Socket FD。
- SmartRenew 的 MySQL、Redis、RabbitMQ 和 LLM HTTP 调用都涉及 Socket IO；但没有证据时不能宣称项目直接编写 epoll 或 Netty。
- Java 21 虚拟线程降低等待任务占用平台线程的成本，但不会取消系统调用、FD、连接池和内核网络栈，见 [[操作系统面试精炼笔记/07-Java21虚拟线程与IO]]。

> [!danger] 高频错误
> - “Java read 就是 Linux read”错误：Java API 可能纯内存读取，也可能被缓冲合并。
> - “每次 Java read 都系统调用”错误：具体实现和缓冲会改变调用次数。
> - “JNI 就是 native 代码”错误：JNI 是交互接口，native code 才是本机代码实体。
> - “系统调用就是中断”错误：应用主动系统调用、硬件异步中断、当前指令异常是三类来源。
> - “FD 就是普通文件”错误：它可引用 Socket、管道、设备等。
> - “Socket 就是一对端口”错误：TCP 连接由四元组区分，监听与已连接 Socket 也不同。

## 高频面试题

### 1. Java InputStream.read 与 Linux read 是什么关系？

- **30 秒答案**：Java read 是 API 调用，访问外部文件/网络时可能经 JDK 实现、JVM/native 层转成 OS read/recv；但 ByteArrayInputStream 可纯内存读取，BufferedInputStream 也会让多次 Java read 复用一次底层读取。
- **追问方向**：缓冲为什么减少系统调用？文件页缓存处在哪一层？
- **常见错误答案**：两者一一对应，每次 Java read 都陷入内核。

### 2. 系统调用、中断和异常有什么区别？

- **30 秒答案**：系统调用由应用主动触发以请求内核服务；中断由硬件异步触发；异常由当前指令同步触发，如缺页。三者都可能进入内核处理，但来源与返回语义不同。
- **追问方向**：Page Fault 属于哪类？网卡收包怎样唤醒 read？
- **常见错误答案**：只要进入内核就都叫中断。

### 3. native code 和 JNI 有什么区别？

- **30 秒答案**：native code 是编译为本机指令的代码；JNI 是 Java 与这类代码交互的一套接口规范和桥梁。JDK/JVM 可以通过 JNI 或内部机制调用 native 能力。
- **追问方向**：系统调用是否必须经过 JNI？为什么 native 阻塞影响虚拟线程？
- **常见错误答案**：JNI 就是一段 C 代码。

### 4. FD 是什么，为什么 Socket 也能用 FD 表示？

- **30 秒答案**：FD 是当前进程 FD 表中的整数索引，指向内核打开对象。Linux 用统一句柄抽象访问文件、管道、设备和 Socket，但 Socket 的内核对象与网络语义仍不同于普通文件。
- **追问方向**：FD 泄漏怎么查？close 是否删除文件？
- **常见错误答案**：FD 保存了文件内容，Socket 本质就是磁盘文件。

### 5. listen Socket 和 accept 后的 Socket 有什么区别？

- **30 秒答案**：监听 Socket 绑定地址并负责接受新连接；accept 为具体连接返回新的 connected FD。监听 FD 仍继续接受其他连接，已连接 Socket 用于双方数据收发。
- **追问方向**：TCP 连接四元组是什么？一个端口能否服务多个连接？
- **常见错误答案**：accept 后监听 FD 被直接变成连接 FD。

### 6. read 阻塞时 CPU 在做什么？

- **30 秒答案**：阻塞的是调用线程，不是 CPU。线程进入等待队列后，调度器让 CPU 运行其他可运行线程；数据到达使 Socket ready，等待线程被唤醒后仍要重新获得 CPU。
- **追问方向**：非阻塞 read 返回什么？epoll_wait 等待有何不同？
- **常见错误答案**：CPU 在原地循环等网络数据。

### 7. 文件系统的基本作用是什么？

- **30 秒答案**：把路径和名称映射到文件对象，维护权限与元数据，分配和定位数据空间，并通过缓存、日志或同步机制提供相应持久化语义。
- **追问方向**：inode 与文件名关系？df 和 du 为什么可能不同？
- **常见错误答案**：文件系统只负责把文件顺序写进磁盘。
