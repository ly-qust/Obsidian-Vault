# 用户态、内核态、系统调用与文件描述符

> 当前面试主入口：[[操作系统面试精炼笔记/00-操作系统知识地图]]
> 本文建立 Java/Linux I/O 的 OS 映射，不展开具体网络协议。

## 一句话结论

用户态代码不能直接执行所有特权操作，系统调用提供受控入口；文件描述符是进程访问内核对象的整数句柄，不等于文件内容本身。

## 1. 用户态与内核态

- **用户态**：普通应用代码运行的权限级别，不能直接操作硬件、页表和内核管理结构。
- **内核态**：内核代码运行的权限级别，可以管理 CPU、内存、设备、进程和文件系统。
- 二者不是“两个 CPU”：通常是同一执行流因权限和入口不同而处于不同运行级别。

一次典型访问的因果链：

```text
Java/Linux 应用发起操作
→ 库函数准备参数
→ 执行系统调用指令
→ CPU 切入内核态并校验参数/权限
→ 内核访问文件、设备或网络对象
→ 返回结果或错误码
→ 回到用户态继续执行
```

系统调用会带来边界切换和参数校验成本，但不是所有 Java 方法调用都会进入内核；纯用户态计算通常不会因为调用普通方法就发生系统调用。

## 2. 文件描述符 FD

文件描述符是进程打开文件、管道、Socket、设备等内核对象后的非负整数索引。常见标准描述符：

| FD | 约定用途 |
|---|---|
| 0 | 标准输入 stdin |
| 1 | 标准输出 stdout |
| 2 | 标准错误 stderr |

简化关系：

```text
进程 FD 表
→ 指向打开文件表项
→ 指向文件/管道/Socket 等内核对象
→ 由内核维护偏移、状态、权限和引用关系
```

同一个文件可以被多个 FD 引用；`close` 只关闭当前进程的一个引用，不等于立刻删除磁盘文件。FD 泄漏会导致“Too many open files”，所以资源必须成对打开和关闭。

## 2.1 `open/read/write/close` 基本系统调用链

```text
open(path, flags)
→ 内核解析路径、检查权限并创建/复用打开文件表项
→ 返回当前进程中的 FD
read(fd, buffer, size)
→ 内核校验 FD 和可读权限
→ 从页缓存或设备取得数据，推进文件偏移，返回实际字节数/EOF/错误
write(fd, buffer, size)
→ 内核校验 FD 和可写权限
→ 写入页缓存或设备，推进文件偏移，返回实际写入字节数/错误
close(fd)
→ 释放当前进程的 FD 引用，必要时触发后续刷新或回收
```

这条链路是面试中的简化模型；具体是否命中页缓存、何时落盘、是否阻塞，取决于文件系统、设备、缓存和打开标志。

## 3. 阻塞/非阻塞与同步/异步

这两组概念关注不同维度：

| 维度 | 关注问题 | 典型含义 |
|---|---|---|
| 阻塞/非阻塞 | 调用不满足条件时是否暂不返回 | 阻塞调用等待；非阻塞调用立即返回当前结果 |
| 同步/异步 | 结果完成由谁负责等待或通知 | 同步调用方参与等待/取结果；异步提交后由系统或运行时在完成时通知 |

因此“非阻塞一定异步”“同步一定阻塞”都不严谨：非阻塞调用可以由调用方轮询，也可以配合事件通知；异步 API 的底层实现也可能使用线程或队列。回答时先说清自己讨论的是调用返回方式，还是完成通知方式。

## 4. 文件系统基本概念

一次路径访问的简化链路：

```text
路径名
→ 逐级查找目录项（名字到文件对象的映射）
→ 找到 inode 等文件元数据
→ 定位数据块或页缓存
→ 通过 FD 读写并由内核维护偏移/权限
```

- **普通文件**：字节序列及其元数据；目录本身也是用于组织名字到文件对象映射的特殊文件。
- **inode**：通常保存权限、所有者、大小、时间和数据块定位等元数据；文件名不等于 inode。
- **目录项 dentry**：帮助内核把路径中的名字解析到文件对象。
- **超级块**：描述文件系统整体布局、容量和状态等信息。
- **页缓存**：内核缓存近期文件数据，读写速度和落盘时机受缓存、设备和同步策略影响。

Linux 常见目录可用“配置、日志、用户、程序、设备”记忆：`/etc`、`/var/log`、`/home`、`/usr`、`/dev`。`df` 更偏文件系统容量，`du` 更偏目录/文件占用，不能混为一谈。

## 5. Java / Linux 关联

- Java 的 `InputStream`、`OutputStream`、`Files`、Socket API 是高层抽象，底层可能通过 JVM、C 库和系统调用访问 FD；不要把 Java 对象直接说成 FD。
- `Path`/`Files` 面向文件系统操作，`java.nio` 提供更丰富的缓冲和 Channel 抽象，但出现 “NIO” 不代表所有操作自动非阻塞。
- Linux 可用 `/proc/<pid>/fd` 查看进程打开的 FD，用 `lsof -p <PID>` 辅助定位；`ulimit -n` 反映进程可用 FD 数量上限，具体还受系统配置影响。
- `ps`、`top` 观察进程资源，`df`/`du` 观察文件系统和目录占用，`journalctl` 观察服务错误；遇到 FD 耗尽要区分连接未关闭、文件句柄泄漏和上限过小。
- Java 虚拟线程可以改善等待型任务的载体占用，但不会取消 FD、连接池和下游容量限制，回看 [[java知识/Java21虚拟线程]]。

## 容易答错点

- “用户态不能访问文件”：应用可以请求文件操作，但要通过系统调用让内核代为完成。
- “系统调用就是普通函数调用”：系统调用会跨权限边界并进入内核处理，成本和语义不同。
- “FD 就是文件”：FD 是当前进程中的句柄，可能指向管道、Socket、设备等非普通文件对象。
- “close 后文件一定被删除”：close 只释放当前打开引用；删除是另一个目录项操作。

## 高频追问

1. 为什么 I/O 比内存访问慢？——可能包含设备等待、内核处理、权限边界、拷贝和调度等待，具体路径取决于对象和缓存。
2. 一个进程为什么会 FD 耗尽？——打开后未关闭、连接/文件生命周期管理错误，或并发规模超过配置上限。
3. `read` 返回 0 和阻塞有什么区别？——对普通文件通常表示到达 EOF；阻塞表示当前条件未满足、调用暂时不能返回。
4. `java.nio` 是不是一定非阻塞？——不是；NIO 是一组 API/抽象，文件操作仍可能阻塞，是否非阻塞要看对象、方法和运行时。
5. `df` 和 `du` 有什么区别？——`df` 看文件系统视角的可用/已用空间，`du` 统计目录树可见文件占用，删除但仍被进程打开的文件可能造成两者结果不一致。
